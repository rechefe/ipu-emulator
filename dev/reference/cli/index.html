    Command-line tools¶

    Every command-line tool in the repository, with its subcommands and options. The option tables are generated at docs build time from each tool's own option declarations (docs/cli_reference_page.py), so they list exactly what the tool parses. Run any of them through bazel run; everything after -- goes to the tool. Relative paths are read from the directory you run bazel in. Every tool also takes --help.

    Assembler: ipu-as¶

    ipu-as assembles, disassembles, checks and formats IPU assembly. A source can be a Jinja2 template: --define gives the values its ipu:params header declares, and -I adds include directories after the source's own one.

    bazel run //src/ipu-as:ipu-as -- assemble --input "$PWD/prog.asm" --output "$PWD/prog.bin" --define rows=8

    assemble writes bin for an --output ending in .bin and mem otherwise, unless --format says which. --target hardware assembles the hardware slots only, and an emulator-only instruction such as BREAK is then an error. check exits 0 for a clean source and 1 otherwise; format exits 1 under --check when the source would change and 3 when it cannot format it.

    ipu-as assemble¶

    Assembles the given input file.

    ipu-as assemble [OPTIONS]
    Option Value Default Description
    --input PATH required The assembly source to assemble.
    --output PATH required The program file to write.
    --format mem | bin Output format; by default bin for a .bin --output, else mem.
    --define KEY=VALUE, repeatable A template value, checked against the source's ipu:params header. Repeatable.
    -I / --include-dir DIRECTORY, repeatable A directory {% include %} and {% import %} resolve in, after the input's own directory. Repeatable.
    --abi FILE A kernel.toml whose [abi] table names the registers the template reads as {{ cr.<name> }} / {{ lr.<name> }}.
    --target emulator | hardware emulator The word to assemble: every slot, as the emulator runs it, or the hardware slots only (an emulator-only instruction is then an error).

    ipu-as disassemble¶

    Disassembles the given input file.

    ipu-as disassemble [OPTIONS]
    Option Value Default Description
    --input PATH required The program file to read.
    --output PATH required The text file to write.
    --format mem | bin Input format; by default bin for a .bin --input, else mem.
    --target emulator | hardware emulator The word to assemble: every slot, as the emulator runs it, or the hardware slots only (an emulator-only instruction is then an error).
    --syntax fields | assembly fields fields: every field of every slot, by word; assembly: source that assembles back to the same words.

    ipu-as check¶

    Report errors in an assembly source without producing output.

    ipu-as check [OPTIONS]
    Option Value Default Description
    --input TEXT required Source file to check, or "-" to read from stdin.
    --json / --text flag Emit machine-readable diagnostics (used by the VS Code extension).
    --json-version 1 to 2 Which --json layout to print: 1 (the default) is a bare array of diagnostics, 2 is {"schemaVersion": 2, "diagnostics": [...]}.
    --json-versions flag Print the --json versions this assembler supports, as a JSON array, and exit.
    --define KEY=VALUE, repeatable A template value, checked against the source's ipu:params header. Repeatable.
    -I / --include-dir DIRECTORY, repeatable A directory {% include %} and {% import %} resolve in, after the input's own directory. Repeatable.
    --target emulator | hardware emulator The word to assemble: every slot, as the emulator runs it, or the hardware slots only (an emulator-only instruction is then an error).
    --tokens flag Add the semantic tokens of the source. Needs v2.
    --words flag Add whether each word's instructions fit its slots. Needs v2.
    --jinja flag Add the Jinja regions, with the names each defines and uses. Needs v2.

    ipu-as format¶

    Print an assembly source in the repository's layout.

    ipu-as format [OPTIONS]
    Option Value Default Description
    --input FILE required Source file to format, or "-" to read from stdin.
    --check flag Write nothing; exit 1 if formatting would change the source, 0 if not.
    --in-place flag Rewrite the input file instead of printing the result.
    --indent N\|tab 4 One level of indentation: N spaces, or a tab.
    --blank-line flag Separate each ;; word from the next by an empty line.
    --range L1:L2 Format only lines L1 to L2 (1-based, inclusive); the others stay as they are.

    Kernel runner: kernel targets and run_kernel¶

    Each kernel under kernels/ is a Bazel target that runs one of its cases end to end, in one element format or all of them, and checks every output against its golden: bazel run //kernels/<family>/<name>, or //kernels/<family>:<entry> for a family's registry entry. The target passes the kernel itself; the options below come after --. run_kernel takes the kernel's folder instead, for a kernel outside the tree.

    bazel run //kernels/softmax/softmax_rows -- --case constant_row --profile-aliases
bazel run //src/ipu-harness:run_kernel -- path/to/kernel --case default --format all

    Each run prints KERNEL/CASE/FORMAT: PASS cycles=N MAC util=P%, then the fault, if the run faulted, and each output's comparison with its expected values. It exits 0 when every run passed; 1 when a run failed or faulted, or the request was wrong (one line, no traceback); and 2 for a bug in the runner or in the kernel's Python (with the traceback). bazel test on the same label runs every case in every format.

    run_kernel [-h] [--case CASE] [--format FORMAT] [--input NAME=PATH.npy] [--output OUTPUT] [--trace TRACE] [--context CONTEXT] [--max-cycles MAX_CYCLES] [--list-cases] [--benchmark] [--markdown MARKDOWN] [--json JSON] [--debug] [--profile-aliases] [--alias-report ALIAS_REPORT] kernel
    Option Value Default Description
    kernel positional required the kernel's folder (it holds kernel.toml), or REGISTRY.toml::NAME for an entry
    --case CASE default a case name, e.g. 'sweep[rows=7]'
    --format FORMAT an element format, or 'all' (default: the first of the case's formats)
    --input NAME=PATH.npy, repeatable replace an input (repeatable)
    --output OUTPUT write each output as DIR/<name>.npy
    --trace TRACE write the run's trace (JSON Lines)
    --context CONTEXT with --trace, also write the Cycle Inspector's context (JSON): the source, the starting registers, and each word's lanes and XMEM reads
    --max-cycles MAX_CYCLES the cycle limit (0: no limit; default: the model's)
    --list-cases flag list the cases and stop
    --benchmark flag run the [benchmark] points and print their table
    --markdown MARKDOWN with --benchmark, write the table here
    --json JSON with --benchmark, write the rows as JSON here
    --debug flag stop in the debugger TUI
    --profile-aliases flag profile the ISA aliases of the run and print the summary
    --alias-report ALIAS_REPORT write the alias profile as JSON instead (implies profiling; with --format all, PATH.<format>.json each)

    Run statistics¶

    MAC util is the effective MAC utilization of the run, from the counters the reference model keeps for one run (ReferenceModel.stats(), the reference-model API); --benchmark reports them for each [benchmark] point:

    Counter What it counts
    Total cycles Instruction words retired.
    Mult active, Acc active Cycles whose MULT or ACC slot was not a no-op, and their fraction of the total cycles.
    XMEM reads LD.MULT, LD.MULT.CYCLIC and LD.MASK executed.
    XMEM writes ST.ACC and ST.AAQ executed.
    XMEM accesses Reads plus writes.
    Mult idle Cycles whose MULT slot was a no-op.
    Identity mult Active multiply cycles that multiplied by a constant 1 to move data, and their fraction of the active cycles.
    Lane ops Multiplier lanes that passed the mask and lay within valid_elements, summed over every multiply; occupancy is that over the total cycles times 128 lanes.
    Effective MAC Lane ops less the identity multiplies' lanes, over the run's peak: the multiplier work that was real arithmetic.

    The counters describe one run: loading a program resets them, so a second program on the same model reports only itself.

    A run that reaches its cycle limit faults F-9, with the PC of the word that would have run next. The default limit is ipu_emu.emulator.DEFAULT_MAX_CYCLES (1 000 000); --max-cycles N sets it for one run, and 0 removes it. A run that executed an ISA idiom counts it: --profile-aliases prints the idioms' measurements, and --alias-report FILE writes them as JSON.

    Debugger¶

    The debugger is the kernel runner in a terminal user interface: add --config=debug to bazel run on any kernel target. It stops at cycle 0, before the first word runs, and takes the same options as an ordinary run.

    Trace recorder¶

    The kernel runner records a case itself: --trace writes its trace (JSON Lines, the trace schema), and --context adds the context the Cycle Inspector needs beside it.

    bazel run //kernels/reshape/identity -- --case single_row --trace "$PWD/trace.jsonl" --context "$PWD/context.json"

    Kernel query: query¶

    query asks the kernel registry which kernel computes an operation, and why. With no operation it prints the coverage report.

    bazel run //kernels:query -- maxpool2d channels=2 height=8 width=8 kernel_size=7 stride=1 padding=3

    NAME=VALUE parameters go to the registry as given: a value with a comma is a tuple of integers, an integer is an int, a number with a point a float, true and false are booleans, and anything else is a string; format=e4 limits the answer to one element format. It exits 0 when the query is covered (for a sweep, every value) and 1 when it is not.

    query [-h] [--sweep NAME=START..END] [--json] [op] [NAME=VALUE ...]
    Option Value Default Description
    op positional operation, e.g. scale (omit for the coverage report)
    NAME=VALUE positional, repeatable kernel parameters
    --sweep NAME=START..END the routing table as NAME runs
    --json flag print the verdict as JSON (one query)
