    IPU Assembly Instruction Reference¶

    Per-opcode documentation is generated from InstructionDoc entries in instruction_spec.py. Operand types link to the shared operand type reference.

    Slots¶

    A VLIW instruction word encodes one sub-instruction per slot. Slots are grouped into pipeline stages that execute sequentially within a cycle: CTRL (COND + LR run concurrently; LOAD address is resolved here and the data feeds MULT) → MULT → ACC → AAQ → STORE. ACC_STORE, BREAK are emulator-only: not in the hardware word. Any omitted slot is filled with NOP by the assembler automatically.

    Slot Count Tag Description
    COND 1 HARDWARE Conditional and unconditional branches; control flow based on register comparisons.
    LR 3 HARDWARE Loop register instructions for controlling addresses, counters, and scalars. Three independent sub-slots per cycle.
    LOAD 1 HARDWARE First-stage memory loads that feed the multiply unit (mult-stage, cyclic, and mask registers).
    MULT 1 HARDWARE Multiply-stage instructions: element-wise and vector multiply operations.
    ACC 1 HARDWARE Accumulation instructions for combining multiply results into R_ACC.
    AAQ 1 HARDWARE Activation and quantization: apply activation to R_ACC and write quantized INT8 bytes to POST_AAQ_REG.
    STORE 1 HARDWARE Last-stage memory stores that drain POST_AAQ_REG to external memory after activation and quantization.
    ACC_STORE 1 EMULATOR Simulation-only stores of R_ACC to external memory (ST.ACC). Not implemented in real IPU hardware.
    BREAK 1 EMULATOR Debug break: halts execution or enters debug mode.

    NOP — No Operation¶

    Syntax: NOP

    Tag: HARDWARE in the hardware slots, EMULATOR in the emulator-only slots.

    Faults: none (fault list).

    No operation. Every slot accepts NOP. The assembler fills any omitted slot with NOP automatically. When written explicitly in a compound instruction, NOP is assigned to the next unfilled slot in compound-layout order (COND → LR → LOAD → MULT → ACC → AAQ → STORE → ACC_STORE → BREAK).

    Element formats¶

    The element format is selected at run time and sets the element width. Element formats lists the formats and how each encodes values.

    Compound Instruction Layout¶

    The compound (VLIW) instruction word is shown two ways below, first as the hardware word, then as the emulator word.

    • Whole-word bit layout — every operand token in its actual bit position (MSB → LSB), coloured by the owning slot. This is what an encoded VLIW word looks like in memory.
    • Per-slot union layout — for each slot, the union fields packed by the layout solver, with a per-opcode grid showing which operand each opcode places in each field. Useful for seeing where cross-opcode field sharing comes from.

    Conditional Branch Instructions¶

    Control flow instructions for branching based on conditions or unconditionally.

    BEQ — Branch if Equal¶

    Syntax: BEQ reg1 reg2 label

    Tag: HARDWARE (implemented by the IPU)

    Faults: F-2 (fault list).

    Operands: (the Type column links to the operand type reference)

    Name Type Details
    reg1 LcrIdx reg1: First register to compare (LR0–LR15 or CR0–CR15)
    reg2 LcrIdx reg2: Second register to compare (LR0–LR15 or CR0–CR15)
    label Label label: Branch target label

    General description: Branch if two registers are equal.

    Pseudo code: if (reg1 == reg2) PC = label

    Example of usage: 

    BEQ LR0 LR1 end;;
end:
HALT;;

    Register reads: reg1 (LR): cycle start; reg1 (CR): cycle start; reg2 (LR): cycle start; reg2 (CR): cycle start.

    BNE — Branch if Not Equal¶

    Syntax: BNE reg1 reg2 label

    Tag: HARDWARE (implemented by the IPU)

    Faults: F-2 (fault list).

    Operands: (the Type column links to the operand type reference)

    Name Type Details
    reg1 LcrIdx reg1: First register to compare (LR0–LR15 or CR0–CR15)
    reg2 LcrIdx reg2: Second register to compare (LR0–LR15 or CR0–CR15)
    label Label label: Branch target label

    General description: Branch if two registers are not equal.

    Pseudo code: if (reg1 != reg2) PC = label

    Example of usage: 

    loop:
INC LR0 1;;
BNE LR0 CR0 loop;;

    Register reads: reg1 (LR): cycle start; reg1 (CR): cycle start; reg2 (LR): cycle start; reg2 (CR): cycle start.

    BLT.S — Branch if Less Than (signed)¶

    Syntax: BLT.S reg1 reg2 label

    Tag: HARDWARE (implemented by the IPU)

    Faults: F-2 (fault list).

    Operands: (the Type column links to the operand type reference)

    Name Type Details
    reg1 LcrIdx reg1: First register to compare (LR0–LR15 or CR0–CR15)
    reg2 LcrIdx reg2: Second register to compare (LR0–LR15 or CR0–CR15)
    label Label label: Branch target label

    General description: Branch if first register is less than second, as signed 32-bit integers.

    Pseudo code: if (int32(reg1) < int32(reg2)) PC = label # signed 32-bit

    Example of usage: 

    BLT.S LR0 CR1 smaller;;
smaller:
HALT;;

    Register reads: reg1 (LR): cycle start; reg1 (CR): cycle start; reg2 (LR): cycle start; reg2 (CR): cycle start.

    BGE.S — Branch if Greater or Equal (signed)¶

    Syntax: BGE.S reg1 reg2 label

    Tag: HARDWARE (implemented by the IPU)

    Faults: F-2 (fault list).

    Operands: (the Type column links to the operand type reference)

    Name Type Details
    reg1 LcrIdx reg1: First register to compare (LR0–LR15 or CR0–CR15)
    reg2 LcrIdx reg2: Second register to compare (LR0–LR15 or CR0–CR15)
    label Label label: Branch target label

    General description: Branch if first register is greater than or equal to second, as signed 32-bit integers.

    Pseudo code: if (int32(reg1) >= int32(reg2)) PC = label # signed 32-bit

    Example of usage: 

    BGE.S LR0 CR1 ge;;
ge:
HALT;;

    Register reads: reg1 (LR): cycle start; reg1 (CR): cycle start; reg2 (LR): cycle start; reg2 (CR): cycle start.

    BR — Branch Register¶

    Syntax: BR reg

    Tag: HARDWARE (implemented by the IPU)

    Faults: F-2 (fault list).

    Operands: (the Type column links to the operand type reference)

    Name Type Details
    reg LcrIdx reg: Register containing target address (LR0–LR15 or CR0–CR15)

    General description: Branch to address in register.

    Pseudo code: PC = reg

    Register reads: reg (LR): cycle start; reg (CR): cycle start.

    HALT — Halt¶

    Syntax: HALT

    Tag: HARDWARE (implemented by the IPU)

    Faults: none (fault list).

    General description: End the kernel after every slot of this word has retired.

    Unconditional. The other slots of the same word retire first; then the kernel is done. To stop for debugging, use BREAK (emulator-only) instead. Not the host's HALT command, which stops a running kernel.

    Pseudo code: no further fetch; kernel done when this word retires

    Example of usage: 

    HALT;;

    LR Instructions¶

    Loop register manipulation instructions for controlling loop counters and addresses.

    SET — Set Loop Register¶

    Syntax: SET reg src

    Tag: HARDWARE (implemented by the IPU)

    Faults: F-3 (fault list).

    Operands: (the Type column links to the operand type reference)

    Name Type Details
    reg LrIdx reg: Loop register (LR0–LR15)
    src CrIdx src: Source configuration register (CR0–CR15)

    General description: Copy a 32-bit value from a configuration register into a loop register.

    Pseudo code: reg = cr[src]

    Example of usage: 

    SET LR0 CR1;;

    Register reads: src (CR): cycle start.

    ADD — Add¶

    Syntax: ADD dest src_a src_b

    Tag: HARDWARE (implemented by the IPU)

    Faults: F-3 (fault list).

    Operands: (the Type column links to the operand type reference)

    Name Type Details
    dest LrIdx dest: Destination local register (LR0–LR15)
    src_a LrIdx src_a: First source local register (LR0–LR15)
    src_b LcrIdx src_b: Second source — LR0–LR15 or CR0–CR15

    General description: Add two register sources and store the result in the destination LR.

    Pseudo code: dest = src_a + src_b

    Example of usage: 

    ADD LR0 LR1 LR2;;
ADD LR3 LR1 CR5;;

    Register reads: src_a (LR): cycle start; src_b (LR): cycle start; src_b (CR): cycle start.

    SUB — Subtract¶

    Syntax: SUB dest src_a src_b

    Tag: HARDWARE (implemented by the IPU)

    Faults: F-3 (fault list).

    Operands: (the Type column links to the operand type reference)

    Name Type Details
    dest LrIdx dest: Destination local register (LR0–LR15)
    src_a LrIdx src_a: First source local register (LR0–LR15)
    src_b LcrIdx src_b: Second source — LR0–LR15 or CR0–CR15

    General description: Subtract the second source from the first and store the result in the destination LR.

    Pseudo code: dest = src_a - src_b

    Example of usage: 

    SUB LR0 LR1 LR2;;
SUB LR3 LR1 CR5;;

    Register reads: src_a (LR): cycle start; src_b (LR): cycle start; src_b (CR): cycle start.

    INC.MODP2 — Increment Loop Register Modulo Power of Two¶

    Syntax: INC.MODP2 dest step k

    Tag: HARDWARE (implemented by the IPU)

    Faults: F-1, F-3 (fault list).

    Operands: (the Type column links to the operand type reference)

    Name Type Details
    dest LrIdx dest: Destination loop register (LR0–LR15); read and written
    step LcrIdx step: Signed 32-bit increment from LR0–LR15 or CR0–CR15
    k LrModPow2KImmediate k: Immediate in [1, 9]; encoded in 4 bits as (k − 1); mask = (1 << k) - 1

    General description: Add a loop or configuration register into the destination loop register, then mask to k low bits (mod 2^k).

    Pseudo code: dest <- (dest + step) & ((1 << k) - 1)

    Example of usage: 

    INC.MODP2 LR2 LR3 4;;

    Register reads: step (LR): cycle start; step (CR): cycle start; dest (LR): cycle start.

    INC — Increment¶

    Syntax: INC dest imm

    Tag: HARDWARE (implemented by the IPU)

    Faults: F-3 (fault list).

    Operands: (the Type column links to the operand type reference)

    Name Type Details
    dest LrIdx dest: Destination local register (LR0–LR15); also the implicit source
    imm LrIncDecImmediate imm: Unsigned immediate; range 0 to 2^W − 1 where W is derived from the LR slot union layout

    General description: Add an unsigned immediate to the destination LR (read-modify-write).

    Pseudo code: dest = dest + imm

    Example of usage: 

    INC LR0 7;;

    Register reads: dest (LR): cycle start.

    DEC — Decrement¶

    Syntax: DEC dest imm

    Tag: HARDWARE (implemented by the IPU)

    Faults: F-3 (fault list).

    Operands: (the Type column links to the operand type reference)

    Name Type Details
    dest LrIdx dest: Destination local register (LR0–LR15); also the implicit source
    imm LrIncDecImmediate imm: Unsigned immediate; range 0 to 2^W − 1 where W is derived from the LR slot union layout

    General description: Subtract an unsigned immediate from the destination LR (read-modify-write).

    Pseudo code: dest = dest - imm

    Example of usage: 

    DEC LR0 3;;

    Register reads: dest (LR): cycle start.

    ADDB — Add Byte (Broadcast, Register)¶

    Syntax: ADDB dest src_b

    Tag: HARDWARE (implemented by the IPU)

    Faults: F-3 (fault list).

    Operands: (the Type column links to the operand type reference)

    Name Type Details
    dest LrdIdx dest: Destination register pair (LRD0, LRD2, LRD4, ..., LRD14 — named after the lower register); LRDn = LR(n+1):LR(n), 8 byte elements; also the implicit source
    src_b LcrIdx src_b: LR0–LR15 or CR0–CR15; low byte is read and reinterpreted as a signed two's-complement byte

    General description: Broadcast-add a signed byte from an LR/CR register's low byte to each of the 8 byte elements of an LRDn register pair, saturating each element to [0, 255].

    There is no separate subtract opcode: since src_b's byte is reinterpreted as signed, a value ≥ 128 (i.e. negative in two's complement) subtracts from every element instead of adding. E.g. an LR/CR whose low byte is 200 (== -56) decreases each element by 56. Because elements saturate at both ends of [0, 255], subtracting past 0 clamps at 0 rather than wrapping — it does not behave like a plain two's-complement subtract.

    Pseudo code: byte_val = src_b & 0xFF # interpreted as signed int8 (two's complement) for i in 0..7: dest_byte[i] = clamp(dest_byte[i] + byte_val, 0, 255)

    Example of usage: 

    ADDB LRD0 LR3;;
ADDB LRD2 CR5;;

    Register reads: src_b (LR): cycle start; src_b (CR): cycle start; dest (LR): cycle start.

    ADDBI — Add Byte Immediate (Broadcast)¶

    Syntax: ADDBI dest imm

    Tag: HARDWARE (implemented by the IPU)

    Faults: F-3 (fault list).

    Operands: (the Type column links to the operand type reference)

    Name Type Details
    dest LrdIdx dest: Destination register pair (LRD0, LRD2, LRD4, ..., LRD14 — named after the lower register); LRDn = LR(n+1):LR(n), 8 byte elements; also the implicit source
    imm AddbiImmediate imm: Unsigned byte 0–255 (or an equivalent signed −128–127 literal); reinterpreted as a signed two's-complement byte for the add

    General description: Broadcast-add a signed immediate byte to each of the 8 byte elements of an LRDn register pair, saturating each element to [0, 255].

    There is no separate subtract opcode: write imm as a negative literal (e.g. -56) or its equivalent unsigned encoding (200) to subtract from every element instead of adding — both spellings encode the same bit pattern. Because elements saturate at both ends of [0, 255], subtracting past 0 clamps at 0 rather than wrapping — it does not behave like a plain two's-complement subtract.

    Pseudo code: byte_val = imm # interpreted as signed int8 (two's complement) for i in 0..7: dest_byte[i] = clamp(dest_byte[i] + byte_val, 0, 255)

    Example of usage: 

    ADDBI LRD0 200;;
ADDBI LRD2 7;;

    Register reads: dest (LR): cycle start.

    LOAD Instructions¶

    First-stage memory loads that feed the multiply unit (mult-stage registers, cyclic register, and mask register).

    LD.MULT — Load Register¶

    Syntax: LD.MULT dest offset base

    Tag: HARDWARE (implemented by the IPU)

    Faults: F-1, F-6, F-7 (fault list).

    Operands: (the Type column links to the operand type reference)

    Name Type Details
    dest MultStageReg dest: R0 | R1 — mult-stage register to load (2-bit field; only these encodings are valid).
    offset LrIdx offset: LR0…LR15 — offset register, in XMEM rows.
    base CrIdx base: CR0…CR15 — base address register, in XMEM rows.

    General description: Load data from memory into a multiplication stage register.

    Pseudo code: dest = Memory[row(offset + base)] # one row = 128 elements (128 B narrow, 512 B wide-vector debug)

    Example of usage: 

    SET LR0 CR1;;
LD.MULT R0 LR0 CR0;;

    Register reads: offset (LR): after LR writes; base (CR): cycle start.

    LD.MULT.CYCLIC — Load Cyclic Register¶

    Syntax: LD.MULT.CYCLIC offset base index

    Tag: HARDWARE (implemented by the IPU)

    Faults: F-4, F-6, F-7 (fault list).

    Operands: (the Type column links to the operand type reference)

    Name Type Details
    offset LrIdx offset: Offset register (LR0–LR15), in XMEM rows.
    base CrIdx base: Base address register (CR0–CR15), in XMEM rows.
    index LrIdx index: Index inside cyclic register (LR0–LR15); must hold 0, 128, 256, or 384 — the four R_CYCLIC slot boundaries, counted in elements. Any other value raises an error. All four are valid in both modes: R_CYCLIC is a 512-element ring in narrow and wide-vector debug mode alike, and a load always replaces one whole 128-element slot.

    General description: Load with cyclic addressing into R_CYCLIC.

    Pseudo code: R_CYCLIC[index .. index+127] = Memory[row(offset + base)] # index ∈ {0, 128, 256, 384}

    Register reads: offset (LR): after LR writes; base (CR): cycle start; index (LR): after LR writes.

    LD.MASK — Load Mask Register¶

    Syntax: LD.MASK offset base

    Tag: HARDWARE (implemented by the IPU)

    Faults: F-6, F-7 (fault list).

    Operands: (the Type column links to the operand type reference)

    Name Type Details
    offset LrIdx offset: Offset register (LR0–LR15), in XMEM rows.
    base CrIdx base: Base address register (CR0–CR15), in XMEM rows.

    General description: Load mask data from memory.

    Pseudo code: R_MASK = Memory[row(offset + base) .. +128B] # reads only the row's first 128 B, in both modes -- the mask is 1 bit/element and does not scale with element width

    Register reads: offset (LR): after LR writes; base (CR): cycle start.

    MULT Instructions¶

    Multiplication instructions for element-wise and element-vector operations. The multiplication result (mult_result) is forwarded to the ACC stage in the CPU and not stored in any register in the way.

    MULT.RC.VV — RC Vector × Ra Vector Multiply¶

    Syntax: MULT.RC.VV rc_idx ra mask_offset mask_shift cr_idx

    Tag: HARDWARE (implemented by the IPU)

    Faults: F-1 (fault list).

    Operands: (the Type column links to the operand type reference)

    Name Type Details
    rc_idx LrIdx rc_idx: LR0…LR15 — base ELEMENT index into R_CYCLIC (cyclic, mod 512 elements; same unit as LD.MULT.CYCLIC's index).
    ra MultStageReg ra: R0 | R1 — multiplicand mult-stage register (same cycle as LD.MULT into R0/R1 is allowed).
    mask_offset MultMaskOffsetImmediate mask_offset: immediate mask slot 0…7 — selects one of eight 128-bit masks in R_MASK.
    mask_shift LrIdx mask_shift: LR0…LR15 — index ∈ [−3, +3] (values >3 clamp to 3, values <−3 clamp to −3) selecting one of seven masks via sequential shift-and-AND: positive indices use partition_vector (0 at group start), negative indices use inverse_partition_vector (0 at group end).
    cr_idx DstructureCrIdx cr_idx: CR0…CR15 — dstructure register supplying the partition field used to build the partition vectors and the pad_mode field used to fill deactivated elements (must be given explicitly).

    General description: Multiply R_CYCLIC[rc_idx:rc_idx+128] by Ra (R0 or R1) element-wise. The partition used by mask_shift comes from cr_idx's dstructure configuration (any CR0-CR15; must be named explicitly).

    Element masking via mask_offset and mask_shift fills elements whose derived mask bit is 0 (deactivated) in MULT_RES with the dstructure register's pad_mode value (zero by default, or +inf/-inf for a floating-point dtype) before accumulation; elements with bit 1 pass through. See Masking for the full algorithm.

    Pseudo code: For each element i: MULT_RES[i] = ipu_mult(R_CYCLIC[(rc_idx + i) % 512], ra[i]); then apply mask and shift using CR[cr_idx].partition.

    Example of usage: 

    MULT.RC.VV LR0 R0 0 LR2 CR15;;

    Register reads: rc_idx (LR): after LR writes; ra (R): cycle start; mask_shift (LR): after LR writes; R_CYCLIC: cycle start; R_MASK: cycle start; cr_idx (CR): cycle start.

    MULT.RC.VE — RC Vector × Scalar Multiply¶

    Syntax: MULT.RC.VE rc_idx src mask_offset mask_shift cr_idx

    Tag: HARDWARE (implemented by the IPU)

    Faults: none (fault list).

    Operands: (the Type column links to the operand type reference)

    Name Type Details
    rc_idx LrIdx rc_idx: LR0…LR15 — base ELEMENT index into R_CYCLIC (cyclic, mod 512 elements; same unit as LD.MULT.CYCLIC's index).
    src LcrIdx src: LR0…LR15 | CR0…CR15 — if an LR, its stored value selects the scalar from R0/R1 (0..127 → R0[idx], 128..255 → R1[idx - 128]); if a CR, its low element-width bits, decoded in the active format, are the scalar (CR1 reads as 1; see CrIdx and CR scalars).
    mask_offset MultMaskOffsetImmediate mask_offset: immediate mask slot 0…7 — selects one of eight 128-bit masks in R_MASK.
    mask_shift LrIdx mask_shift: LR0…LR15 — index ∈ [−3, +3] (values >3 clamp to 3, values <−3 clamp to −3) selecting one of seven masks via sequential shift-and-AND: positive indices use partition_vector (0 at group start), negative indices use inverse_partition_vector (0 at group end).
    cr_idx DstructureCrIdx cr_idx: CR0…CR15 — dstructure register supplying the partition field used to build the partition vectors and the pad_mode field used to fill deactivated elements (must be given explicitly).

    General description: Multiply R_CYCLIC[rc_idx:rc_idx+128] by a scalar, element-wise. The scalar is either a single element of R0/R1 (selected by an LR value) or a CR register value. The partition used by mask_shift comes from cr_idx's dstructure configuration (any CR0-CR15; must be named explicitly).

    Element masking via mask_offset and mask_shift fills elements whose derived mask bit is 0 (deactivated) in MULT_RES with the dstructure register's pad_mode value (zero by default, or +inf/-inf for a floating-point dtype) before accumulation; elements with bit 1 pass through. See Masking for the full algorithm.

    Pseudo code: For each element i: MULT_RES[i] = ipu_mult(R_CYCLIC[(rc_idx + i) % 512], src_value); then apply mask and shift using CR[cr_idx].partition.

    Example of usage: 

    MULT.RC.VE LR0 LR3 0 LR2 CR15;;

    Register reads: rc_idx (LR): after LR writes; mask_shift (LR): after LR writes; src (LR): after LR writes; src (CR): cycle start; R: cycle start; R_CYCLIC: cycle start; R_MASK: cycle start; cr_idx (CR): cycle start.

    MULT.RC.VS — RC Vector Self-Multiply (Square)¶

    Syntax: MULT.RC.VS rc_idx mask_offset mask_shift cr_idx

    Tag: HARDWARE (implemented by the IPU)

    Faults: none (fault list).

    Operands: (the Type column links to the operand type reference)

    Name Type Details
    rc_idx LrIdx rc_idx: LR0…LR15 — base ELEMENT index into R_CYCLIC (cyclic, mod 512 elements; same unit as LD.MULT.CYCLIC's index).
    mask_offset MultMaskOffsetImmediate mask_offset: immediate mask slot 0…7 — selects one of eight 128-bit masks in R_MASK.
    mask_shift LrIdx mask_shift: LR0…LR15 — index ∈ [−3, +3] (values >3 clamp to 3, values <−3 clamp to −3) selecting one of seven masks via sequential shift-and-AND: positive indices use partition_vector (0 at group start), negative indices use inverse_partition_vector (0 at group end).
    cr_idx DstructureCrIdx cr_idx: CR0…CR15 — dstructure register supplying the partition field used to build the partition vectors and the pad_mode field used to fill deactivated elements (must be given explicitly).

    General description: Square R_CYCLIC[rc_idx:rc_idx+128] element-wise. The partition used by mask_shift comes from cr_idx's dstructure configuration (any CR0-CR15; must be named explicitly).

    Element masking via mask_offset and mask_shift fills elements whose derived mask bit is 0 (deactivated) in MULT_RES with the dstructure register's pad_mode value (zero by default, or +inf/-inf for a floating-point dtype) before accumulation; elements with bit 1 pass through. See Masking for the full algorithm.

    Pseudo code: For each element i: rb = R_CYCLIC[(rc_idx + i) % 512]; MULT_RES[i] = ipu_mult(rb, rb); then apply mask and shift using CR[cr_idx].partition.

    Example of usage: 

    MULT.RC.VS LR0 0 LR2 CR15;;

    Register reads: rc_idx (LR): after LR writes; mask_shift (LR): after LR writes; R_CYCLIC: cycle start; R_MASK: cycle start; cr_idx (CR): cycle start.

    Pseudo code: For each element i: ra = Ra[(ra_idx + i) % 256]; MULT_RES[i] = ipu_mult(ra, CR[cr_idx][0]); then apply mask and shift using CR[dstructure_cr_idx].partition.

    ACC.STRIDE — Accumulator Stride¶

    Syntax: ACC.STRIDE elements_in_row horizontal_stride vertical_stride offset

    Tag: HARDWARE (implemented by the IPU)

    Faults: F-1 (fault list).

    Operands: (the Type column links to the operand type reference)

    Name Type Details
    elements_in_row ElementsInRow elements_in_row: Elements per row (16, 32, or 64; minimum is 16)
    horizontal_stride HorizontalStride horizontal_stride: Horizontal stride mode (off, on, on_inv)
    vertical_stride VerticalStride vertical_stride: Vertical stride mode (enabled, inverted)
    offset LrIdx offset: LR register; value % 4 gives start index in RACC (0, 32, 64, or 96)

    General description: Reorder the multiplication result into R_ACC using horizontal/vertical stride decimation. Only updates the RACC indexes written; leaves the rest unchanged.

    Pseudo code: Decimate MULT_RES as rows×cols; apply horizontal stride (take every 2nd column); then vertical stride (take every 2nd row). Write result into R_ACC[start:start+N] where start = (offset%4)*32, N = 32|64|128. When a data structure has fewer than 8 elements, hardware pads to 16 automatically (not programmable).

    Example of usage: 

    ACC.STRIDE 16 off off LR0;;

    Register reads: offset (LR): after LR writes; MULT_RES: same-cycle forward.

    AGG.SUM.FIRST — Aggregate Sum (First)¶

    Faults: none (fault list).

    Operands: (the Type column links to the operand type reference)

    Name Type Details
    dest_slot LrIdx dest_slot: LR register whose value gives the destination slot in R_ACC (0–127)

    General description: Sum active MULT_RES elements and write the result into R_ACC at the slot given by LR.     Example of usage:

    Register reads: dest_slot (LR): after LR writes; cr_idx (CR): cycle start; MULT_RES: same-cycle forward.

    ACC.RESHAPE — Reshape¶

    Syntax: ACC.RESHAPE source dest reshape_mask

    Tag: HARDWARE (implemented by the IPU)

    Faults: F-5 (fault list).

    Operands: (the Type column links to the operand type reference)

    Name Type Details
    source LrdIdx source: LRDn register pair (LRD0, LRD2, ..., LRD14) read as source[0..7] — 8 byte elements, each a MULT_RES word index
    dest LrdIdx dest: LRDn register pair (LRD0, LRD2, ..., LRD14) read as dest[0..7] — 8 byte elements, each an R_ACC word index
    reshape_mask LrOrReshapeMaskImmediate reshape_mask: immediate 0-7 or an LR register; selects the first participating element index (elements reshape_mask..7 participate; reshape_mask = 0 uses all 8, reshape_mask = 7 uses only element 7). When an LR is given, its full value is used as the mask at runtime.

    General description: Scatter MULT_RES elements into R_ACC: for each of the trailing (8 - reshape_mask) byte elements of the source/dest LRDn pairs (indices reshape_mask..7), copy MULT_RES[source[i]] to R_ACC[dest[i]].

    reshape_mask skips the lowest-indexed elements 0..reshape_mask-1; the rest participate. Example: reshape_mask = 2 skips elements 0, 1; elements 2-7 participate. Example: reshape_mask = 5 skips elements 0-4; elements 5-7 participate.

    Pseudo code: mult_res = MULT_RES (this cycle's MULT result) mask = reshape_mask if immediate else LR[reshape_mask] if mask > 8: raise error for i in mask..7: if source[i] >= 128 or dest[i] >= 128: raise error R_ACC[dest[i]] = mult_res[source[i]]

    Example of usage: 

    ACC.RESHAPE LRD0 LRD2 0;;

    Register reads: source (LR): after LR writes; dest (LR): after LR writes; reshape_mask (LR): after LR writes; MULT_RES: same-cycle forward.

    AAQ Instructions¶

    Activation and quantization: apply activation to R_ACC elements and write quantized INT8 bytes to POST_AAQ_REG.

    ACTIVATE.QUANTIZE — Activate and Quantize¶

    Syntax: ACTIVATE.QUANTIZE activation_fn cr_idx

    Tag: HARDWARE (implemented by the IPU)

    Faults: F-1 (fault list).

    Operands: (the Type column links to the operand type reference)

    Name Type Details
    activation_fn ActivationFn activation_fn: keyword naming the activation (one of identity, relu, relu6, sigmoid, tanh, gelu, softplus, elu, exp2, reciprocal, rsqrt, silu, window; see ACTIVATION_FN_NAMES)
    cr_idx DstructureCrIdx cr_idx: CR0…CR15 supplying valid_elements (must be given explicitly)

    General description: Read active elements from the forwarded R_ACC (this cycle's ACC result), apply the selected element-wise activation, clamp the results to the INT8 range [-128, 127], and write the resulting bytes to the leading active-element positions of POST_AAQ_REG; all remaining bytes are zeroed. r_acc is not modified. Requires INT8 mode. The active element count is taken from cr_idx's dstructure valid_elements field (any CR0–CR15; must be named explicitly). Available activation functions: identity (0), relu (1), relu6 (2), sigmoid (3), tanh (4), gelu (5), softplus (6), elu (7), exp2 (8), reciprocal (9), rsqrt (10), silu (11), window (12).

    Pseudo code: Requires the INT8 element format (IpuState.fmt == ElementFormat.INT8). Let n = min(CR[cr_idx].valid_elements, 128) and k = encoded activation index. For i in [0, n): POST_AAQ_REG[i] = clamp(round(activation_k(R_ACC[i])), -128, 127). POST_AAQ_REG[n..511] = 0. R_ACC is not modified. Clamping is a placeholder until a full per-element requantize is implemented. The selector uses four bits; encodings outside the thirteen named activations behave as identity. window(x) = 1 for a <= x < b and 0 otherwise. α for elu and the window bounds a, b are not ISA operands; see docs/content/reference/isa/activate-quantize.md.

    Example of usage: 

    ACTIVATE.QUANTIZE relu CR15;;

    Register reads: cr_idx (CR): cycle start; R_ACC: same-cycle forward.

    Last-stage memory stores that drain POST_AAQ_REG to external memory after activation and quantization.

    ST.AAQ — Store Post-AAQ register¶

    Syntax: ST.AAQ offset base

    Tag: HARDWARE (implemented by the IPU)

    Faults: F-6, F-7 (fault list).
