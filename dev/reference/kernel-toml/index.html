    kernel.toml¶

    Every key a kernel's kernel.toml takes, and a family's registry.toml. For a walk-through that builds a kernel step by step, see Write a kernel.

    A kernel.toml declares everything about a kernel except its program: its parameters and their domain, its input, output and scratch regions, which register holds each value, its cases, and how outputs are checked. The harness reads it once (ipu_harness.manifest.load_manifest) and every later step reads that checked view. An error names the file, the line and the key, for example kernels/elementwise/scale/kernel.toml:14: [abi] binds CR1, a hardwired constant. An unknown key names the closest valid one.

    The text below comes from the loader's own documentation, and the table of keys from the key lists it checks against, so the page changes when the schema does.

    Schema¶

    [kernel] (required)¶

    op (str, required): the operation, also the shared reference's name. formats (list, required): element formats the kernel runs in, by their ipu_isa.formats.ElementFormat names (fp32, int8, e1..e7, int32). asm (path): the program, default <folder>.asm. stages ("file.py:fn"): a multi-program pipeline (E06-14). cost: what routing (E06-16) minimises among the kernels that accept a query: a number (negative to prefer a kernel), or an expression in the shape grammar over integer parameter and derived names; default 0.

    [params.<name>] (or <name> = { ... } under [params])¶

    type (required): int, float, bool or str. min and max (int and float), multiple_of (int, at least 1), choices (a non-empty list, each in the domain), default, and unit: count (default), rows or bytes (bytes only for a kernel in BYTE_UNIT_KERNELS, L16). Floats are finite. query_required (bool, default false): a routing query that leaves the parameter out is refused at this kernel, naming it, whatever its default; a case takes its own or the default value as before.

    [inputs.<name>], [outputs.<name>], [scratch.<name>]¶

    shape (non-empty list, required): positive ints, or expressions over parameter and derived names in E06-03's grammar ("rows * 4", "ceil(k / 128)"). row: pin the region's first XMEM row (Q81), an int or an expression like a shape's, which may also read row_bytes, the bytes of one row in the case's format ("131072 / row_bytes" pins the region at byte 0x20000 in every format: a legacy layout). after ("<tensor>"): place the region right after that tensor's in placement order (by default inputs, then outputs, then scratch, each in file order), so scratch can come before an output; not with row. when ("<bool param>" or "not <bool param>", such terms joined by and, and those joined by or: "has_bias or apply_relu", "not has_bias and not apply_relu"): the tensor exists only in a case where that holds; otherwise it is not placed, generated, passed to the reference or bound. pack (inputs and outputs): a named pack transform (E06-05); an output's lays out the stored rows that ipu_harness.packing.unpack reads back. store (outputs): element (default) or accumulator. fill (scratch): the value the region is filled with, default 0: a number, or an expression over int and float parameters and derived values in the shape grammar, evaluated exactly when the case is planned ("-1 / channels", whole or not; a float parameter is its exact binary value) and rounded to the format when stored. bytes (scratch, not with fill): "file.py:fn", or "../file.py:fn" in the family's folder as a generator may be, fn(plan) returns the region's exact starting bytes, format-blind (a lane mask, which no element value can carry). The runner writes either through ipu_harness.packing.region_fill. Scratch regions are placed and filled, never compared. range (inputs): [lo, hi] for the generated values in every format, or { int8 = [lo, hi], e4 = [lo, hi] } per format (E06-08); lo may equal hi (a constant input).

    [abi]¶

    <name> = "CR2" .. "CR15", or "LR0" .. "LR15" (a preset, E06-06). CR0 and CR1 are hardwired constants and cannot be bound, except that a tensor pinned at a literal row = 0 may bind CR0: the program reads its base through the hardwired 0 and nothing is written. A binding may be a table with register and optional keys: a tensor's may add offset, { register = "CR2", offset = -1 } for its base row plus an int (in a unit = "bytes" kernel the base and the offset count bytes). Any binding may be a table with when (as a tensor's): it binds only in a case where that holds; a conditional tensor's binding takes the tensor's condition. Two bindings may share a register only when their conditions exclude each other (bias and not bias; a condition with or excludes another only when every term of one contradicts every term of the other), or when both are tensors pinned at literal rows that put the same value in it (acc at row = 8 and relu = { register = "CR7", offset = -12 } at row = 20: the program reaches relu from acc's base). A float parameter (an element scalar) binds a CR. Every key names a parameter, a tensor or a derived value, and every tensor is bound (its base row must reach the program), itself or through a bound [derived] value that reads its base().

    [derived]¶

    <name> = "<expression>" over parameters and earlier derived values, in the shape grammar (E06-06). An expression may also read base(<tensor>), the region's base row once placed (in bytes in a unit = "bytes" kernel, as a tensor's binding): such a value, and any that reads it, is placed (KernelManifest.placed), known only when the registers are written, so only [abi] binds it; a shape, a pin or the cost cannot read it. w1 = "base(weights) + 1" gives one region several offset registers, which a { register, offset } binding cannot. A value that reads row_bytes (the bytes of one XMEM row in the case's format) is placed too: "512 / row_bytes" is the rows one accumulator vector spans (4 in an 8-bit format, 1 in FP32 and INT32).

    [cases.<name>]¶

    Parameter values: a scalar, or a non-empty list (a sweep axis). Reserved keys: formats (a non-empty subset of the kernel's), inputs and expected (tensor name to a user file, Q82; an expected may instead be "file.py:fn", or "../file.py:fn" in the family's folder, whose fn(plan) returns the output's values in the case's format: a golden kept in another encoding, such as fully_connected's .bin), generator ("file.py:fn", or "../file.py:fn" in the family's folder, a generator its kernels share), tier (default or nightly, Q73). [cases.default] is required.

    [benchmark] (optional, E06-11)¶

    points: a non-empty list of tables of parameter values, each over the default case's, which must take one value each (one run per point and format, paired, not swept; a point keeps the default case's generator but not its files, and may not change a registry entry's fixed parameter); per: an int parameter the report divides cycles by; max_cycles: each run's limit (the model's by default). It needs a [golden] reference or op, which each point is held to; no two points may be equal. python -m ipu_harness.cli KERNEL --benchmark (bazel run :<kernel> -- --benchmark) runs them; ipu_harness.benchmark.

    [golden] (optional)¶

    reference ("file.py:fn"; default reference.py:reference when the kernel has a reference.py) or op (a shared reference in ipu_kernels.reference), not both; tolerance (format to a tier name of ipu_harness.tolerance.TIERS, or a table overriding a tier's numbers: tier and why (required), rtol, atol, ulps; a key is a format some output is compared in: a format the kernel runs in for an element output, its accumulator format (FP32, INT32) for an accumulator output, so a key no output reads is an error; an override may set only what compare reads for that format: ulps only for an 8-bit float, and then not rtol/atol; a format not listed is compared at EXACT).

    Every declared name (parameter, tensor, derived value) is an identifier that does not start with _ and is not cr, lr or a reserved case key. Every file path stays inside the kernel directory: .. and absolute paths are refused (checked lexically). A case generator's file that is not in the kernel's folder is its family folder's (kernels/<family>/gen.py), as a pack transform may be the family folder's pack.py: a family's templates share them. An unknown section or key is an error that names the closest valid one.

    A family registry.toml entry (E06-17, ipu_harness.family) loads its template with overrides: name, formats (a subset), params (fixed values: each becomes the parameter's only choice and its value in every case; a default the template gives stays, so a query that leaves the parameter out means that default, else the fixed value stands in) and cases (the template cases the entry runs, default among them).

    Every key¶

    The tables and keys the loader accepts; any other key is an error that names the closest valid one.

    Table Keys
    [kernel] op, formats, asm, stages, cost
    [params.<name>] type, min, max, multiple_of, choices, default, unit, query_required
    [inputs.<name>] shape, row, after, when, pack, range
    [outputs.<name>] shape, row, after, when, pack, store
    [scratch.<name>] shape, row, after, when, fill, bytes
    [abi] table binding register, offset, when
    [cases.<name>] (reserved keys) formats, inputs, expected, generator, tier
    [golden] reference, op, tolerance
    [golden] tolerance override tier, rtol, atol, ulps, why

    registry.toml¶

    A family declares its variants, kernels that differ from a template kernel only in parameter values, as entries of kernels/<family>/registry.toml. An entry is its template's kernel.toml with the entry's params fixed: each becomes the parameter's only value. A default the template gives stays, so a query that leaves the parameter out means that default, and an entry fixing another value refuses it. Without one the entry's value stands in, and a query that leaves out a parameter its entries fix differently is refused for it. The entry runs the template's cases with those values, in the template's formats unless it narrows them. Its Bazel targets are //kernels/<family>:<name>, :<name>_nightly and :assemble_<name>.

    # kernels/projections/registry.toml
[[kernel]]
name = "proj_ffn1_192_p4"        # kernel name == Bazel target name
template = "proj_p4"             # kernels/projections/proj_p4/ (an ordinary kernel folder)
params = { k = 192, n_out = 384, n_tok = 64, n_tg = 1, activation = "silu" }
doc = "Layer 4 FFN1"             # one line, for the kernel page and query output
formats = ["fp32"]               # optional: a subset of the template's
cases = ["default", "edge"]      # optional: the template cases it runs, default among them

    A [[kernel]] entry takes name, template, params, formats, cases, doc.

    Bazel reads the entries from the generated registry.bzl beside the TOML. After editing registry.toml, rewrite it:

    bazel run //kernels:update_registry_bzl

    The family's registry_bzl_test fails while registry.bzl is stale.
