    Reference model API¶

    ipu_emu.reference is the emulator's stable interface for RTL verification. A cocotb testbench resets the model, loads a program, sets registers and XMEM, steps it one word at a time and compares each commit record with what the RTL retired. How-to: use the reference model from cocotb walks through a testbench.

    API version 2.0.0 (ipu_emu.reference.API_VERSION); commit record schema 1.1.0, trace header schema 1.0.0.

    The API, schema and fault sections of this page are generated from the code and the schema files, so they always match the version above.

    Compatibility¶

    The contract is:

    • the names in ipu_emu.reference.__all__, with their signatures, dataclass fields and enum values;
    • the commit records step() returns (ipu_emu.commit), field by field;
    • the commit record and trace header schemas, which are language-neutral JSON Schema files in ipu_isa/schemas/.

    Everything else in ipu_emu is internal and can change in any release. The other symbols on this page (TraceWriter, the schema helpers, the argument types) are listed because the contract hands them out or takes them, not as a separate promise.

    API_VERSION is a semantic version:

    • Major (breaking): a public name removed or renamed, a parameter removed or made required, a field removed, renamed or retyped, or a meaning changed (a method that now refuses what it accepted, a field that now counts something else). Version 2.0.0 is the run modes of ADR 0007: ElementFormat keeps FP32 and NX8 (value "nx8") and loses INT8, E1–E7 and INT32, so the constructor and reset() take one of the two modes, and the constructor defaults to NX8 instead of INT8; load_program() refuses a program that uses the FP32-only ACTIVATE.EXACT when the model runs in NX8 mode, and reset() refuses to switch a model holding such a program to NX8; the post_aaq_reg register bank is removed, and read_register() and write_register() take the r_meta, r_cyclic_meta and aaq_lut banks as bytes; and a commit record's slots no longer include store or acc_store, and can include aaq_exact. It also adds the XMEM metadata side store: read_xmem_metadata(), write_xmem_metadata() and the CommitRecord.xmem_meta_writes field (default empty), with the commit record schema's optional xmem_meta_writes (schema 1.1.0). The other method signatures and commit record fields are 1.4.0's.
    • Minor: an addition that leaves every existing call working, such as a new method, a new optional parameter or a new dataclass field with a default. Version 1.1.0 added Stats and stats(); 1.2.0 added the flag and enable reads (fault_enabled(), fault_flags(), arith_flags()), trace_header(), and TraceWriter and read_trace to __all__; 1.3.0 added debug_run(), attach_alias_profile(), alias_profile() and the RunResult.quit field (default False); 1.4.0 added observe_xmem_reads(), which reports each XMEM read the program makes (a commit record carries writes only; the Cycle Inspector's recorder shows the reads). Nothing earlier changed.

    debug_run() is the one escape hatch for tools such as the debugger: its callback receives the emulator's internal state, and that argument's type, like its control argument's, is outside the contract. The method's signature and what it returns follow the version.

    Each schema carries its own version, at the end of its $id. An optional field added is a minor bump; a field removed or renamed, or a meaning changed, is a major one. A trace header names the commit record schema's version (schema_version).

    Two tests hold the promise. src/ipu-emu/test/test_reference_api_contract.py pins every public name, signature and record field under the version that introduced it, so a surface change fails until a new version's entry matches. src/ipu-emu/test/test_commit.py pins each schema file's bytes to its version. A strict mypy test (//src/ipu-emu:mypy_reference) types the module.

    A lockstep test¶

    from pathlib import Path

from ipu_emu.reference import ReferenceModel
from ipu_isa.formats import ElementFormat


async def test_lockstep(dut):
    model = ReferenceModel()
    model.reset(ElementFormat.NX8)
    model.load_program(Path("prog.bin").read_bytes())  # a program file, or its words as ints
    model.write_register("lr", 5, index=0)              # LR0 = 5
    model.write_xmem(0, bytes(range(128)))              # XMEM row 0

    while True:
        record = model.step()                           # one word's CommitRecord
        rtl = await rtl_retire(dut)                     # your testbench's own monitor
        assert record.to_json() == rtl
        if record.outcome in ("halt", "fault"):         # model.status names the fault
            break

    step() returns the word's commit record, the same object a run writes to a trace. Its outcome is retired, halt or fault: the model never stops at a BREAK slot, so break does not occur. A stepped record's cycle counts the words since the last reset() or load_program(); in a trace run() writes, it counts the trace's records, as the schema says.

    Rules¶

    • The model is HALTED after a reset, a program load or a HALT word, and RUNNING once stepped. After a HALT word or a fault, status.pc is that word's PC.
    • The host accesses the IPU refuses with an AXI error raise ConfigurationError: writing a register, XMEM or a program while running; writing CR0 or CR1 (constants in hardware); a bank, index or range that does not exist; a value that does not fit.
    • After a fault, step(), run(), load_program() and the register and XMEM writes raise ConfigurationError until reset() (IPU-FLT-7). After a HALT word, step() and run() raise it until reset() or load_program().
    • No method returns an emulator object: values are ints, floats, bytes, the dataclasses below and CommitRecord.
    • Registers are named by bank, as ipu_isa.registers names them (lr: LR0-LR15, cr: CR0-CR15, r: R0-R1, ...), and index picks the register within the bank. r_wide_debug and r_cyclic_wide_debug are emulator-only banks: they hold the operands of the FP32 mode, which the hardware does not have; r_meta and r_cyclic_meta hold the row metadata of R0, R1 and each R_CYCLIC slot in the NX8 mode.

    Arguments

    • fmt: The run mode's element format to start in, NX8 (the default) or FP32 (reset changes it; 2.0.0 removed the other formats, ADR 0007).
    ReferenceModel.reset()¶
    ReferenceModel.reset(fmt: ElementFormat) -> None

    Reset the model. The loaded program stays.

    Registers and XMEM go to their reset values (CR15.L holds the default DS), the PC to 0, every fault is enabled with no sticky flag, and the arithmetic flags and the statistics clear. Record numbering restarts at 0.

    Arguments

    • fmt: The element format to run in.

    Raises

    • ConfigurationError: fmt is no element format, or it is NX8 and the loaded program uses ACTIVATE.EXACT (FP32 only). The model is left as it was.
    ReferenceModel.load_program()¶
    ReferenceModel.load_program(words: bytes | Sequence[int]) -> None

    Load a program, only while halted. The PC goes to 0 and record numbering restarts at 0.

    Arguments

    • words: A program file's bytes (ipu-as .bin), or its words as unsigned ints.

    Raises

    • ConfigurationError: The model is running or faulted (after a fault, reset first); the bytes are not whole words; a word is wider than the instruction word; the program is larger than IMEM; or the model runs in NX8 mode and the program uses the FP32-only ACTIVATE.EXACT (2.0.0).

    ReferenceModel.observe_xmem_reads()¶
    ReferenceModel.observe_xmem_reads(callback: Callable[[int, int], None]) -> Callable[[], None]

    Report every XMEM read the program makes (1.4.0): callback(address, size) in bytes, as each word reads. A commit record carries the word's writes only; a viewer that shows its reads (the Cycle Inspector) takes them from here. Host accesses (read_xmem, write_xmem) are not reported.

    Returns

    ReferenceModel.step()¶
    ReferenceModel.step() -> CommitRecord

    Run one word. A BREAK slot never stops it (Q39): the word retires. A step has no cycle limit (F-9 is run's); its word counts toward the statistics' cycles.

    Returns

    • The word's commit record; its outcome is retired, halt or fault (never break), and its cycle counts the words since the last reset or load_program.

    Raises

    • ConfigurationError: The model is faulted (IPU-FLT-7: reset first), or stopped after a HALT word or past IMEM (reset or load a program first).
    ReferenceModel.run()¶
    ReferenceModel.run(max_cycles: int | None = None, *, trace: TraceWriter | None = None) -> RunResult

    Step until a HALT word, a fault, or the cycle limit (fault F-9).

    Arguments

    • max_cycles: The cycle limit of this run: None keeps the model's, 0 disables it.
    • trace: Where to write each word's commit record, as it retires; None keeps none. Its records number from 0 (the schema's cycle: records before this one in the trace).

    Returns

    • The status the run stopped in and the words it retired.

    Raises

    • ConfigurationError: As step.
    ReferenceModel.debug_run()¶
    ReferenceModel.debug_run(callback: DebugCallback, break_on_entry: bool = False, *, max_cycles: int | None = None, control: RunControl | None = None) -> RunResult

    Run as run does, stopping for a debugger (1.3.0).

    The one escape hatch for tools such as ipu_debug: at each stop (a breakpoint or run target in control, a BREAK slot that fires, a step, or the entry when break_on_entry) it calls callback(state, cycles) with the emulator's internal state and the words retired so far, and the callback's DebugAction says whether to continue, step or quit (ipu_emu.emulator.run_with_debug's contract). Unlike the rest of this API, the callback's argument type and control's are internal and may change in any release; the method itself, and what it returns, follow API_VERSION.

    Arguments

    • callback: Called at each stop; returns a DebugAction.
    • break_on_entry: Stop before the first word.
    • max_cycles: The cycle limit of this run, as for run.
    • control: The breakpoints and run target to honour, shared with a debugger frontend (ipu_emu.run_control.RunControl); a fresh one when None.

    Returns

    • The status the run stopped in, the words it retired, and quit: whether the callback returned QUIT or Ctrl-C ended the run. A Ctrl-C at a stop leaves the model between words; one during a word may leave it partly done, and a later step or run re-runs it from the start (its finished part applies twice, and the statistics other than cycles may already count it), so reset or load_program when results must be exact. A QUIT pauses the model where it stopped (RUNNING): a later step or run carries on from that PC. A callback that also moves the PC past IMEM (ipu_debug's quit) leaves the model HALTED there: the host may write again, and stepping needs reset or load_program. A callback that moves the PC past IMEM without QUIT leaves the model RUNNING there: its next fetch faults F-2.

    Raises

    • ConfigurationError: As step.

    Stats¶

    class Stats  # ipu_emu.reference.Stats

    The run statistics since the program started (1.1.0).

    They count every word retired since the last ReferenceModel.reset or ReferenceModel.load_program, stepped or run (a faulting word retires nothing, so it adds nothing). They depend on operand values (a multiply by a constant 1.0 is an identity multiply), so a commit record does not carry them.

    A frozen dataclass.

    Field Type Default Meaning
    cycles int The words retired.
    mult_active_cycles int Words whose MULT slot was not NOP.
    acc_active_cycles int Words whose ACC slot was not NOP.
    xmem_reads int XMEM rows read.
    xmem_writes int XMEM rows written.
    mult_lane_ops int Multiplier lanes that carried data (passed the mask and lay within valid_elements), summed over every multiply.
    mult_identity_lane_ops int The part of mult_lane_ops that multiplied by a constant 1.0 (data routing, not MACs).
    lane_occupancy float mult_lane_ops / (cycles * LANES); 0.0 before the first word.
    effective_mac_utilization float (mult_lane_ops - mult_identity_lane_ops) / (cycles * LANES), the fraction of peak MACs retired; 0.0 before the first word.

    Commit record and trace schema¶

    A commit record's JSON form (CommitRecord.to_json()) is a document of the commit record schema. A trace is a JSON Lines file: a header line of the trace header schema, then one commit record per word. Download the schema files to validate either with any JSON Schema (draft 2020-12) validator.

    IPU commit record, version 1.1.0 (commit_record.v1.json): One retired VLIW word (E04-29). Integers up to 32 bits are JSON numbers; wider data are lowercase hex strings, little-endian. Register names are ipu_isa's. NOP slots are omitted. A write is a range the word wrote, with its value at the end of the cycle. A faulting word has no effect (precise faults), so a fault record has no writes.

    Field Type Required Meaning
    cycle integer (≥ 0) yes Records before this one in the trace.
    pc_before integer (0 to 4294967295) yes The word's PC.
    pc_after integer (0 to 4294967295) yes The PC of the next word.
    slots array of object yes The word's ops, one per non-NOP slot.
    slots[].slot string yes The slot, as ipu_isa.slots names it.
    slots[].mnemonic string yes The op's mnemonic.
    slots[].fields object of integer (0 to 4294967295) yes The encoded operand values, by operand name.
    slots[].tag "emulator" no Present only on an op with no hardware equivalent.
    reg_writes array of object yes The registers the word wrote, at their end-of-cycle values.
    reg_writes[].register string yes The bank, as ipu_isa.registers names it.
    reg_writes[].index integer (≥ 0) yes, in form 1 of 2 A scalar register (lr, cr): the register within the bank.
    reg_writes[].value integer (0 to 4294967295) yes, in form 1 of 2 A scalar register: its unsigned 32-bit value.
    reg_writes[].tag "emulator" no Present only on a register with no hardware equivalent (wide-vector debug).
    reg_writes[].offset integer (≥ 0) yes, in form 2 of 2 A vector register: the first byte written, within the bank.
    reg_writes[].data string (^([0-9a-f]{2})*$) yes, in form 2 of 2 A vector register: the bytes written.
    xmem_writes array of object yes The XMEM ranges the word wrote.
    xmem_writes[].address integer (0 to 4294967295) yes The first XMEM byte written.
    xmem_writes[].data string (^([0-9a-f]{2})*$) yes The bytes written.
    outcome one of "retired", "break", "halt", "fault" yes break: the word's BREAK slot fired, and the word retired when the run went on. halt: a HALT word retired. fault: the word faulted (fault says which).
    fault null or object yes The fault the word raised, or null.
    fault.id string (^F-[1-9]$) yes The fault ID, as the fault list writes it.
    fault.pc integer (0 to 4294967295) yes The faulting word's PC.
    arith_events array of string yes Arithmetic events of the word (E04-23); empty until they are modelled.
    xmem_meta_writes array of object no Optional (1.1.0): the XMEM metadata words the word wrote, one per 128-byte unit, at their end-of-cycle values. A record with none may leave the field out.
    xmem_meta_writes[].address integer (0 to 4294967295) yes The first byte of the 128-byte XMEM unit the word describes.
    xmem_meta_writes[].value integer (0 to 65535) yes The unit's 16-bit metadata word (ADR 0007: scale[7:0], dynamic_exponent[8]).
    • When outcome is "fault": fault is an object, reg_writes is empty, xmem_writes is empty, xmem_meta_writes is empty. Otherwise fault is null.

    IPU trace header, version 1.0.0 (trace.v1.json): A trace is JSON Lines: this header on the first line, then one commit record (commit_record schema) per line (E04-29).

    Field Type Required Meaning
    schema_version string (^[0-9]+\.[0-9]+\.[0-9]+$) yes The commit record schema's version.
    isa_digest string (^[0-9a-f]{64}$) yes SHA-256 of the ISA definition (ipu_isa.trace_schema.isa_digest).
    format string yes The element format the program ran in.
    program_digest string (^[0-9a-f]{64}$) yes SHA-256 of the program as it is loaded: each IMEM word up to the program length, packed little-endian in its emulator word width (ipu_isa.codec.word.word_bytes()), an empty word as zeros.
    emulator_version string yes The version of the model that wrote the trace (ipu_emu.trace.EMULATOR_VERSION for this emulator).

    arith_events holds the names of ipu_isa.faults.ArithmeticEvent: acc_overflow, nan_result, quant_saturation, sorted. An event never halts the model.

    Faults¶

    A faulting word's commit record has outcome fault and names the fault in fault.id; status.fault is the same fault as a FaultId. These are the IDs of the fault list; the emulator section of Faults says what the model checks for each.

    ID FaultId Fault Detected in In the model
    F-1 FaultId.F1 A slot holds a reserved opcode or a reserved operand encoding. ctrl Reported.
    F-2 FaultId.F2 CTRL fetches at a PC at or beyond the program length, by sequential flow, branch or BR. ctrl Reported.
    F-3 FaultId.F3 Two LR lanes of one word write the same LR. ctrl Reported.
    F-4 FaultId.F4 The index of LD.MULT.CYCLIC is not 0, 128, 256 or 384. ctrl Reported.
    F-5 FaultId.F5 ACC.RESHAPE has a mask above 8, or a participating source or destination index of 128 or more. ctrl Reported.
    F-6 FaultId.F6 A load or a store addresses a table that is not configured, or a row beyond the table size. cache_agent Reported.
    F-7 FaultId.F7 A load addresses a write-only table, or a store addresses a read-only table. cache_agent Never raised: the emulator has no table configuration, so no table is read-only or write-only.
    F-8 FaultId.F8 A word stalls for longer than a programmable limit. cache_agent Not modelled: never reported; the emulator has no stall model (OQ-28).
    F-9 FaultId.F9 A kernel runs for more cycles than a programmable limit. ctrl Reported.

    Conformance suite¶

    src/ipu-isa/conformance/ holds the ISA's expected behaviour as data: for each case a program (program.asm, program.bin), its starting state (setup.json, schema setup.schema.json) and the trace of its run (expected.trace.jsonl). No case contains Python, so another implementation (the RTL under cocotb, another model) needs only these files and the schemas.

    To run the suite against another implementation, for each case:

    1. Skip it if setup.json has "emulator_only": true.
    2. Reset in the case's format and load program.bin.
    3. Zero every register and XMEM byte (CR0 and CR1 aside), then write the registers, XMEM regions and XMEM row metadata words of setup.json and set its fault enables.
    4. Run until HALT, a fault or max_cycles, recording a commit record per word.
    5. Compare the header's schema_version, isa_digest, format and program_digest with the expected trace's, then each record, field by field.

    The suite's README.md has the details of each step. bazel test //src/ipu-emu:test_conformance runs every case through this API.
