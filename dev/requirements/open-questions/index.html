    Open questions¶

    An open question blocks the requirement or the block specification that links to it. To close a question, move its answer into the requirement and delete the row.

    Questions OQ-18 onwards concern the emulator and the ISA definition, not only the hardware requirements.

    Faults¶

    ID Question Proposal Owner
    OQ-1 Which illegal states does the IPU detect, and what does each do? The fault list, rows F-1 to F-9, and the arithmetic events Yuval Harary
    OQ-2 What does a word do when its fault enable bit is clear? Decide per fault. For F-1, the slot with the reserved encoding executes as NOP. Yuval Harary

    Conflicts between existing documents¶

    ID Topic Conflict Proposal Owner
    OQ-3 CR and LR width The control spec diagram says 20 bits. Its text and the instruction reference say 32 bits. 32 bits Unassigned
    OQ-4 IMEM bank depth The control spec says 128 words per bank and a 7-bit PC. The branch label field is 10 bits. The emulator holds 1024 words. 1024 words per bank and a 10-bit PC, as a parameter Unassigned
    OQ-5 SET source The instruction reference takes a CR index only. The control spec takes a 5-bit source with a signed immediate mode. CR index only Unassigned
    OQ-6 AAQ behaviour and element data types The instruction reference has 13 activation functions in a 4-bit field, requires INT8 mode and clamps to INT8. The AaQ spec has 7 function types in a 3-bit field and quantizes FP32 to a format and a scale. The AaQ spec is the hardware behaviour. The instruction reference calls its clamp a placeholder. State which element data types the hardware supports. Unassigned
    OQ-7 Store row format The instruction reference stores 512 bytes. The AaQ spec stores 1039 bits. The cache unit spec has 1024-bit rows with 16 bits of metadata. 128 elements of 8 bits, plus 16 bits of metadata. The element format is a table property. Unassigned
    OQ-8 Row address to table mapping CTRL produces CR[base] + LR[offset]. The cache unit expects {table_id, offset[19:0]}. No document defines the mapping. The 24-bit sum is {table_id[3:0], offset[19:0]}. The base CR carries the table ID. Unassigned
    OQ-9 Load and use in one word The instruction reference allows LD.MULT and a MULT that reads the same register in one word. The control spec tells software to avoid it. Allowed. The MULT slot sees the data the LOAD slot of the same word fetched. This matches IPU-ARCH-1. Unassigned
    OQ-10 LR values in the ACC slot The control spec forwards LR values from after the LR writes of the word. The accumulator spec marks dest_slot, source and dest as values from before the word, and offset as the value after. One rule for all slots after CTRL: values from after the LR writes (IPU-ARCH-3) Unassigned

    Kernel flow¶

    ID Question Proposal Owner
    OQ-11 How does a kernel hand a table to the next kernel inside XMEM, with no DRAM round trip? The banks carry the context bit of the first kernel. The second kernel hits only on its own context bit. The cache unit retags the handed-over banks at kernel_done. The table set of the next kernel names the table it inherits. Cache unit owner
    OQ-12 What does the cache unit do with the XMEM banks of a kernel on kernel_abort? The cache unit frees every bank of the aborted context and drains none. Cache unit owner
    OQ-13 How does the host run the kernel in the active context again from IDLE? ARM always starts the inactive context. ARM takes a context argument in IDLE. Unassigned

    Interfaces¶

    ID Question Proposal Owner
    OQ-14 What is the width of the hardware VLIW word, and how does it pack into 32-bit AXI beats? Width answered (E03-22): the emulator word without the ACC_STORE and BREAK slots, 155 bits (IPU_COMPOUND_INST_WIDTH in the generated SV package, word_bits(Tag.HARDWARE) in ipu_isa.layout), 160 bits (20 bytes) padded to 32-bit beats.     Pipeline¶

    ID Question Proposal Owner
    OQ-16 How do CTRL and the cache agent meet 1 GHz? IPU-ARCH-17 commits LR writes only when the cache agent accepts the word, and IPU-MEM-1 decides in the cycle CTRL presents the word. Option A: the cache agent decides in the CTRL cycle. Option B: it decides one cycle later and CTRL restores the LR file and the PC when the word is not accepted. Choose in the CTRL and cache agent specifications. Unassigned
    OQ-17 What happens when a word loads a row that an older word in the pipeline stores to? The store reaches XMEM several cycles after the load reads it. Scratch-pad and read-after-write tables allow both accesses. The cache agent stalls the load until STORE has written the row. Unassigned

    Emulator and ISA¶

    ID Question Evidence Proposal Owner
    OQ-18 What does the emulator do on an FP32 accumulator overflow or a NaN result? ACC and AGG store the IEEE result (±inf, NaN; an integer wraps) and set the sticky ACC_OVERFLOW or NAN_RESULT flag (E04-23; test_arith_events.py). A float32 overflow in MULT (FP32 only) or AAQ still raises OverflowError: float too large to pack with f format. Follow the arithmetic events: store the IEEE result (±inf, NaN), set the per-event sticky flag, never halt. Emulator change in E04 (faults and sticky arithmetic flags). Close when the arithmetic-events requirement leaves "Proposed". Yuval Harary
    OQ-19 What are the special values of the FP8 formats E1 to E7? The emulator decodes every all-ones exponent as NaN, including mantissa 0, which IEEE-style decoders (ml_dtypes float8_e4m3, float8_e5m2) read as ±inf (ipu_isa.formats.decode_element). Encoding saturates to the maximum finite value on overflow and on ±inf (ipu_isa.formats.encode_element). E4's maximum is 240, not the 448 of OCP E4M3FN. E1 has no normal values. Keep the current convention: all-ones exponent is NaN, saturate on overflow, no infinities. Add OCP formats only if the hardware has them. State the convention in the element-formats page (E09-19). Unassigned
    OQ-20 What is the AaQ stage's behaviour? The emulator's ACTIVATE.QUANTIZE is a placeholder. The emulator implements 13 exact functions in Python (activations.py) and clamps to INT8. Outside wide-vector mode it raises EmulatorError unless the format is INT8 (slots/aaq.py:168), and its clamp sets no quantization-saturation arithmetic event. The AaQ spec has 7 function types evaluated through a LUT, a LOAD operation, an e8m0 block scale and a 1033-bit POST_AAQ_REG payload. See also OQ-6 and OQ-7. It keeps every projection kernel out of E4: each stores through ACTIVATE.QUANTIZE (E07-03). The AaQ spec is the hardware behaviour (as OQ-6). The emulator model is replaced when the spec is complete. Until then, every AaQ row below stays open and unfixed. Unassigned
    OQ-21 What does exp2 return for large inputs? activations.py:127 computes math.exp(x * math.log(2.0)), which raises OverflowError for x above about 1024. The prototype path does the same (slots/aaq.py:62). In wide FP32 mode, results between about 2^128 and 2^1024 are finite doubles, and the FP32 store then raises float too large to pack. Decide with OQ-18 and OQ-20: return +inf and let the quantizer saturate. Unassigned
    OQ-22 How does quantization treat ±inf and NaN? Wide quantize calls int(round(val)) (slots/aaq.py:124), which raises on ±inf (OverflowError) and NaN (ValueError). The INT32 wide path (slots/aaq.py:104) and the narrow path (slots/aaq.py:173) do the same. Saturate ±inf to the format limits and map NaN to 0, before the integer conversion. Decide with OQ-19 and OQ-20. Unassigned
    OQ-23 Which POST_AAQ_REG lanes does an activation write when fewer than 128 elements are valid? The wide non-quantize path writes only the active lanes (slots/aaq.py:100-115); lanes active to 127 keep the previous value. The narrow path zeroes the remaining bytes. ST.AAQ stores all 512 bytes, so stale data reaches XMEM. Zero the inactive lanes, as the narrow path does. Unassigned
    OQ-24 What do reciprocal(0) and rsqrt(0) return? The AaQ spec pseudocode returns inf (MAS-stage-aaq-str.md:188, :190). The spec's function table returns 0 (MAS-stage-aaq-str.md:205-206). The emulator returns 0, and rsqrt returns 0 for every x ≤ 0 (activations.py:128-131). Decide with OQ-20. The answer fixes OQ-27. Unassigned
    OQ-25 How are the AaQ LUT, the LOAD operation and the block scale specified, and when does the emulator model them? The spec describes a 256 × 17-bit LUT plus a 75-bit metadata block filled by LOAD through lut_addr (MAS-stage-aaq-str.md:19, :84-87, :413-471), and an e8m0 block scale (:104, :235-240). The encodings of asymetric and range_mode are TBD (:470). Section 5.1 takes the maximum over i in 0..254 for a 128-element batch (:240). The emulator models none of these. Complete the spec first (owner of the AaQ spec). Then model it behind one AaQ interface in the emulator. Unassigned
    OQ-26 Does the AaQ slot have a LOAD opcode? The AaQ spec declares a 2-bit op with AAQ_INST_OPCODE_LOAD = 2 (MAS-stage-aaq-str.md:84). The ISA and the generated SystemVerilog package define a 1-bit aaq_inst_opcode_t with NOP and ACTIVATE_QUANTIZE only. Adding LOAD changes AAQ_SLOT_T_WIDTH (9 to 10) and IPU_COMPOUND_INST_WIDTH, which is a breaking wire-format change. Correct the spec table to the 1-bit opcode now. Add LOAD as its own ISA change when OQ-25 is answered. Unassigned
    OQ-27 Does LayerNorm add an epsilon before rsqrt? The kernel golden has no epsilon, because rsqrt maps a non-positive variance to 0 (ipu_kernels.reference.ops.layernorm, which every kernels/normalize LayerNorm uses as its golden, E07-10). The MobileViT full-layer chains use the same reference, with no epsilon (kernels/mobilevit/mobilevit_layer.py, E07-24). One reference that matches the kernel, with no epsilon, until AaQ is defined. Revisit with OQ-24. Unassigned
    OQ-28 How is F-8 (word stall limit) checked when the emulator has no stall model? The emulator executes one word per cycle and never stalls, so F-8 can never fire. E04 models the other faults with their IDs and enable bits. List F-8 as "not modelled" in the emulator and in the reference-model contract, until a cache-agent timing model exists. Yuval Harary
    OQ-29 When, and how, does the reference model move to ETISS? Out of scope for the architecture-deepening program. The reference contract is language-neutral: a versioned JSON commit-record and trace schema plus a conformance suite stored as data (ADR 0004), so another implementation can be checked against the same suite. Keep the contract language-neutral. Decide timing and scope (whole model or fast path only) later. Unassigned
    OQ-30 Where does the ELU α default come from, and how is it changed? apply_activation and ActivationParams read the module default DEFAULT_ELU_ALPHA when called or built, so patching it changes the α of states built afterwards; IpuState copies it at construction (activations.py). On hardware α is baked into the loaded LUT (OQ-25). Decide with OQ-20 and OQ-25. Until then, set α through IpuState(activation=ActivationParams(elu_alpha=...)). Unassigned
    OQ-31 After the HALT instruction retires, does the IPU hand off (kernel done: IDLE, or the armed kernel starts) or enter HALTED? IPU-DBG-8 and IPU-EXEC-11 say the kernel is done; the execution flow lists halt requests (the HALT command), breakpoints, step done and faults as the causes that enter HALTED, not the HALT instruction. The emulator ends the run. Kernel done, as IPU-DBG-8 says. The requirements owner confirms. Unassigned
    OQ-32 Does the RTL repository use BRANCH_COND_COUNT as a parameter name? The control spec keeps BRANCH_COND_COUNT = 5 (the branches) and adds COND_OP_COUNT = 6 (branches plus HALT) rather than renaming it. Keep both until the RTL owner says which one the RTL uses. Unassigned
    OQ-33 Where does ACTIVATE.QUANTIZE round, and how many times? The narrow path rounds the activation result (a double) to an integer once (slots/aaq.py:173). The wide FP32 path stores it in POST_AAQ_REG as float32 first and rounds that when wide_vector_quantize_output is set (slots/aaq.py:115, :124), so a result of 0.50000001 quantizes to 0 on the wide FP32 path and to 1 on the narrow path. The wide INT32 path rounds to int32 at activation (slots/aaq.py:104) and clamps without rounding when it quantizes. Found in E04-16. One rounding, from the activation's own precision to the output format, in every format. Decide with OQ-20 and OQ-22. Unassigned
    OQ-34 Is AaqOptions.quantize_output (formerly wide_vector_quantize_output) part of the AaQ model? It is an option of the FP32 and INT32 formats only, held by IpuState.aaq (activations.py, AaqOptions) and read only by ACTIVATE.QUANTIZE (slots/aaq.py:117): without it, FP32 and INT32 activate and do not quantize, and INT8 always quantizes. E04-17 replaced the wide-vector flags with the element format; the AaQ placeholder still carries this option. Found in E04-16. Decide with OQ-20: the AaQ spec says whether quantization is optional. Until then the flag stays an emulator-only AaQ option. Unassigned
    OQ-35 Does ST.AAQ store one XMEM row, or the whole POST_AAQ_REG? The ISA says one row: "Write the whole POST_AAQ_REG to one XMEM row" and Memory[row(offset + base)] = POST_AAQ_REG (instruction_spec.py:282, :290). The emulator writes all 512 bytes of the register from that row (slots/store.py:63), which is four rows in every 8-bit format (128-byte rows) and one in FP32. After ACTIVATE.QUANTIZE in INT8 the register holds 128 results and then zeros, so an 8-bit ST.AAQ also writes zeros to the three rows after its target. The harness's placement does not reserve them; check_aaq_spill (ipu_harness/placement.py) refuses a placement where an element output's spill holds another region or runs past XMEM. It does not check a scratch region stored with ST.AAQ (the legacy maxpool2d_stride2* kernels do), nor an output stored out of row order: the legacy two-group matmul_*_x128 kernels (144x144, 288x144, 432x144, 144x288) store group 1 before group 0's last rows, so in an 8-bit format the spill of group 0's last rows would zero group 1's first three rows, which were already written (they are FP32 today, one row per store). Reserving the spill rows in place() would cover the first; a row-order rule for ST.AAQ outputs, the second. POST_AAQ_REG is 512 bytes only until quantization lands (registers.py); the AaQ stage is a placeholder (OQ-20). Found in E06-15. The two-group projection templates (proj_p4_2tg, proj_p4_2tg_silu, from those matmuls) store the same way, so they run in FP32 only (E07-03). Decide with OQ-20: the AaQ spec says what ST.AAQ stores. One row of the format's elements (128 bytes in INT8) would make the guard unnecessary. Until then the emulator writes 512 bytes and the harness checks the spill. Unassigned
