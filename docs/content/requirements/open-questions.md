# Open questions

An open question blocks the requirement or the block specification that links to it. To close a question, move its answer into the requirement and delete the row.

Questions OQ-18 onwards concern the emulator and the ISA definition, not only the hardware requirements.

| OQ-18 | What does the emulator do on an FP32 accumulator overflow or a NaN result? | ACC and AGG store the IEEE result (±inf, NaN; an integer wraps) and set the sticky `ACC_OVERFLOW` or `NAN_RESULT` flag (E04-23; `test_arith_events.py`). A float32 overflow in MULT (FP32 only) or AAQ still raises `OverflowError: float too large to pack with f format`. | Follow the [arithmetic events](faults.md#arithmetic-events): store the IEEE result (±inf, NaN), set the per-event sticky flag, never halt. | OQ-19 | What are the special values of the FP8 formats E1 to E7? | The emulator decodes every all-ones exponent as NaN, including mantissa 0, which IEEE-style decoders (ml_dtypes `float8_e4m3`, `float8_e5m2`) read as ±inf (`ipu_isa.formats.decode_element`). Encoding saturates to the maximum finite value on overflow and on ±inf (`ipu_isa.formats.encode_element`). E4's maximum is 240, not the 448 of OCP E4M3FN. E1 has no normal values. | Keep the current convention: all-ones exponent is NaN, saturate on overflow, no infinities. Add OCP formats only if the hardware has them. State the convention in the element-formats page (E09-19). | Unassigned |
| OQ-20 | What is the AaQ stage's behaviour? The emulator's `ACTIVATE.QUANTIZE` is a placeholder. | The emulator implements 13 exact functions in Python (`activations.py`) and clamps to INT8. The [AaQ spec](../specs/MAS-stage-aaq-str.md) has 7 function types evaluated through a LUT, a `LOAD` operation, an `e8m0` block scale and a 1033-bit `POST_AAQ_REG` payload. See also OQ-6 and OQ-7. It keeps every projection kernel out of E4: each stores through `ACTIVATE.QUANTIZE` (E07-03). | The AaQ spec is the hardware behaviour (as OQ-6). The emulator model is replaced when the spec is complete. Until then, every AaQ row below stays open and unfixed. | Unassigned |
| OQ-21 | What does `exp2` return for large inputs? | `activations.py:127` computes `math.exp(x * math.log(2.0))`, which raises `OverflowError` for x above about 1024. In wide FP32 mode, results between about 2^128 and 2^1024 are finite doubles, and the FP32 store then raises `float too large to pack`. | Decide with OQ-18 and OQ-20: return +inf and let the quantizer saturate. | Unassigned |
| OQ-22 | How does quantization treat ±inf and NaN? | Wide quantize calls `int(round(val))` (`slots/aaq.py:124`), which raises on ±inf (`OverflowError`) and NaN (`ValueError`). Decide with OQ-19 and OQ-20. | Unassigned |
| OQ-23 | Which `POST_AAQ_REG` lanes does an activation write when fewer than 128 elements are valid? | The wide non-quantize path writes only the `active` lanes (`slots/aaq.py:100-115`); lanes `active` to 127 keep the previous value. The narrow path zeroes the remaining bytes. `ST.AAQ` stores all 512 bytes, so stale data reaches XMEM. | Zero the inactive lanes, as the narrow path does. | Unassigned |
| OQ-24 | What do `reciprocal(0)` and `rsqrt(0)` return? | The AaQ spec pseudocode returns inf (`MAS-stage-aaq-str.md:188`, `:190`). | OQ-25 | How are the AaQ LUT, the `LOAD` operation and the block scale specified, and when does the emulator model them? | The spec describes a 256 × 17-bit LUT plus a 75-bit metadata block filled by `LOAD` through `lut_addr` (`MAS-stage-aaq-str.md:19`, `:84-87`, `:413-471`), and an `e8m0` block scale (`:104`, `:235-240`). | OQ-26 | Does the AaQ slot have a `LOAD` opcode? | The AaQ spec declares a 2-bit `op` with `AAQ_INST_OPCODE_LOAD = 2` (`MAS-stage-aaq-str.md:84`). | OQ-33 | Where does `ACTIVATE.QUANTIZE` round, and how many times? | The narrow path rounds the activation result (a double) to an integer once (`slots/aaq.py:173`). The wide INT32 path rounds to int32 at activation (`slots/aaq.py:104`) and clamps without rounding when it quantizes. Found in E04-16. | One rounding, from the activation's own precision to the output format, in every format. Decide with OQ-20 and OQ-22. | Unassigned |
| OQ-34 | Is `AaqOptions.quantize_output` (formerly `wide_vector_quantize_output`) part of the AaQ model? | It is an option of the FP32 and INT32 formats only, held by `IpuState.aaq` (`activations.py`, `AaqOptions`) and read only by `ACTIVATE.QUANTIZE` (`slots/aaq.py:117`): without it, FP32 and INT32 activate and do not quantize, and INT8 always quantizes. E04-17 replaced the wide-vector flags with the element format; the AaQ placeholder still carries this option. Found in E04-16. | Decide with OQ-20: the AaQ spec says whether quantization is optional. Until then the flag stays an emulator-only AaQ option. | Unassigned |
| OQ-35 | Does `ST.AAQ` store one XMEM row, or the whole `POST_AAQ_REG`? | The ISA says one row: "Write the whole `POST_AAQ_REG` to one XMEM row" and `Memory[row(offset + base)] = POST_AAQ_REG` (`instruction_spec.py:282`, `:290`). The emulator writes all 512 bytes of the register from that row (`slots/store.py:63`), which is four rows in every 8-bit format (128-byte rows) and one in FP32. After `ACTIVATE.QUANTIZE` in INT8 the register holds 128 results and then zeros, so an 8-bit `ST.AAQ` also writes zeros to the three rows after its target. The harness's placement does not reserve them; `check_aaq_spill` (`ipu_harness/placement.py`) refuses a placement where an element output's spill holds another region or runs past XMEM. It does not check a scratch region stored with `ST.AAQ` (the legacy `maxpool2d_stride2*` kernels do), nor an output stored out of row order: the legacy two-group `matmul_*_x128` kernels (144x144, 288x144, 432x144, 144x288) store group 1 before group 0's last rows, so in an 8-bit format the spill of group 0's last rows would zero group 1's first three rows, which were already written (they are FP32 today, one row per store). Reserving the spill rows in `place()` would cover the first; a row-order rule for `ST.AAQ` outputs, the second. `POST_AAQ_REG` is 512 bytes only until quantization lands (`registers.py`); the AaQ stage is a placeholder (OQ-20). Found in E06-15. The two-group projection templates (`proj_p4_2tg`, `proj_p4_2tg_silu`, from those matmuls) store the same way, so they run in FP32 only (E07-03). | Decide with OQ-20: the AaQ spec says what `ST.AAQ` stores. One row of the format's elements (128 bytes in INT8) would make the guard unnecessary. Until then the emulator writes 512 bytes and the harness checks the spill. | Unassigned |
