# Open questions

An open question blocks the requirement or the block specification that links to it. To close a question, move its answer into the requirement and delete the row.

Questions OQ-18 onwards concern the emulator and the ISA definition, not only the hardware requirements.

## Emulator and ISA

| ID | Question | Evidence | Proposal | Owner |
|---|---|---|---|---|
| OQ-18 | What does the emulator do on an FP32 accumulator overflow or a NaN result? | ACC and AGG store the IEEE float32 result (±inf, NaN) and set the sticky `ACC_OVERFLOW` or `NAN_RESULT` flag (E04-23; `test_arith_events.py`). A float32 overflow in MULT (FP32 only) or AAQ still raises `OverflowError: float too large to pack with f format`. | Follow the [arithmetic events](faults.md#arithmetic-events): store the IEEE result (±inf, NaN), set the per-event sticky flag, never halt. Emulator change in E04 (faults and sticky arithmetic flags). Close when the arithmetic-events requirement leaves "Proposed". | Yuval Harary |
| OQ-21 | What does `exp2` return for large inputs? | `ACTIVATE.QUANTIZE` follows the AaQ architecture spec, whose `exp2` takes non-positive inputs only: a positive input is an emulator error ([ADR 0007](https://github.com/rechefe/ipu-emulator/blob/master/docs/adr/0007-operational-aaq-and-nx8.md)). The emulator-only `ACTIVATE.EXACT` computes `math.exp(x * math.log(2.0))` (`activations.py`), which raises `OverflowError` for x above about 1024; results between about 2^128 and 2^1024 are finite doubles, and the FP32 store then raises `float too large to pack`. | Decide with OQ-18: `ACTIVATE.EXACT` returns +inf. | Unassigned |
| OQ-24 | What do `reciprocal(0)` and `rsqrt(0)` return? | The AaQ architecture spec adds epsilon = 2^-127, with the input's sign, to a zero or subnormal input (§4.3.1), so `reciprocal(0)` is 2^127 and `rsqrt` of a negative input is NaN; `ACTIVATE.QUANTIZE` does that ([ADR 0007](https://github.com/rechefe/ipu-emulator/blob/master/docs/adr/0007-operational-aaq-and-nx8.md)). The microarchitecture spec's pseudocode returns inf (`MAS-stage-aaq-str.md:188`, `:190`) and its function table 0 (`:205-206`). The emulator-only `ACTIVATE.EXACT` returns 0, and `rsqrt` 0 for every x ≤ 0 (`activations.py`). | The architecture spec's rule; bring the microarchitecture spec in line (OQ-42). The answer fixes OQ-27. | Unassigned |
| OQ-27 | Does LayerNorm add an epsilon before `rsqrt`? | The kernel golden has no epsilon, because `rsqrt` maps a non-positive variance to 0 (`ipu_kernels.reference.ops.layernorm`, which every `kernels/normalize` LayerNorm uses as its golden, E07-10). The MobileViT full-layer chains use the same reference, with no epsilon (`kernels/mobilevit/mobilevit_layer.py`, E07-24). | One reference that matches the kernel, with no epsilon. The LayerNorm kernels store `rsqrt` with the emulator-only `ACTIVATE.EXACT` (FP32), whose `rsqrt` keeps the 0. Revisit with OQ-24 when a LayerNorm runs in NX8. | Unassigned |
| OQ-28 | How is F-8 (word stall limit) checked when the emulator has no stall model? | The emulator executes one word per cycle and never stalls, so [F-8](faults.md#fault-list) can never fire. E04 models the other faults with their IDs and enable bits. | List F-8 as "not modelled" in the emulator and in the reference-model contract, until a cache-agent timing model exists. | Yuval Harary |
| OQ-29 | When, and how, does the reference model move to ETISS? | Out of scope for the architecture-deepening program. The reference contract is language-neutral: a versioned JSON commit-record and trace schema plus a conformance suite stored as data ([ADR 0004](https://github.com/rechefe/ipu-emulator/blob/master/docs/adr/0004-stable-reference-model-api.md)), so another implementation can be checked against the same suite. | Keep the contract language-neutral. Decide timing and scope (whole model or fast path only) later. | Unassigned |
| OQ-30 | Where does the ELU α default come from, and how is it changed? | `apply_activation` and `ActivationParams` read the module default `DEFAULT_ELU_ALPHA` when called or built, so patching it changes the α of states built afterwards; `IpuState` copies it at construction (`activations.py`). Only the emulator-only `ACTIVATE.EXACT` has `elu`; on hardware α would be baked into the loaded LUT of `generic` (OQ-38). | Decide with OQ-38. Until then, set α through `IpuState(activation=ActivationParams(elu_alpha=...))`. | Unassigned |
| OQ-31 | After the `HALT` instruction retires, does the IPU hand off (kernel done: `IDLE`, or the armed kernel starts) or enter `HALTED`? | IPU-DBG-8 and IPU-EXEC-11 say the kernel is done; the [execution flow](execution-flow.md) lists halt requests (the `HALT` command), breakpoints, step done and faults as the causes that enter `HALTED`, not the `HALT` instruction. The emulator ends the run. | Kernel done, as IPU-DBG-8 says. The requirements owner confirms. | Unassigned |
| OQ-32 | Does the RTL repository use `BRANCH_COND_COUNT` as a parameter name? | The control spec keeps `BRANCH_COND_COUNT = 5` (the branches) and adds `COND_OP_COUNT = 6` (branches plus `HALT`) rather than renaming it. | Keep both until the RTL owner says which one the RTL uses. | Unassigned |
| OQ-36 | What does `ACTIVATE.QUANTIZE` write for an inactive element? | The AaQ architecture spec writes NaN (`ARCH-stage-aaq-str.md` §4.3); NX8 has no NaN code. The microarchitecture spec writes 0 (`MAS-stage-aaq-str.md` §6.2). The emulator writes 0 ([ADR 0007](https://github.com/rechefe/ipu-emulator/blob/master/docs/adr/0007-operational-aaq-and-nx8.md)). | 0, until NX8 defines a NaN code (OQ-37). | Yuval Harary |
| OQ-37 | Does NX8 have NaN and ±inf encodings? | The MULT architecture spec marks it "TBD - ask Jacob" (`ARCH-stage-mult.md` §3.2.1). The AaQ architecture spec leaves elements that quantize to inf or NaN out of the scale (§4.3.2.1), and DS `mask_type` 3 is NaN. The emulator saturates ±inf to the largest magnitude and raises an error for NaN. | Define them, or state that NX8 has none. | Unassigned |
| OQ-38 | How is the AaQ LUT evaluated? | The architecture spec defines the entry points (§4.2.3) but not the 17-bit entry format, nor how a value between entry points is computed. §4.2.2 calls `max_exp_num` a biased exponent; §4.2.3 uses it as `2^max_exp_num`. `range_mode = 3` and the entry order of version 3 are undefined. The emulator stores the LUT bits exactly and evaluates with exact math. | Specify the entry format, the interpolation and the open fields. | Unassigned |
| OQ-39 | Where does the LUT load read its data? | Both specs load a segment from the low 32 words of `R_ACC` (`ARCH-stage-aaq-str.md` §4.2, `MAS-stage-aaq-str.md` §6.3); the architecture spec's `LOAD_LUT` also names `table_id` and `table_offset` that its operation never uses. The hardware reads the segment from XMEM. The emulator's `LD.LUT` reads the first 128 bytes of a row, and a word may not hold `LD.LUT` and another load (one XMEM read port). | Correct both specs to an XMEM read. | Unassigned |
| OQ-40 | What are the published QF and DS layouts? | The architects' 16-bit QF and DS halves ([ADR 0007](https://github.com/rechefe/ipu-emulator/blob/master/docs/adr/0007-operational-aaq-and-nx8.md)) are not in a spec. The architecture specs have two different 32-bit `quantizion_format` layouts (AaQ §3.1, MULT §3.2) and a 32-bit `dstructure` with `pad_mode` at a TBD position (MULT §3.1). The emulator implements the 16-bit drafts. | Publish the 16-bit layouts in both architecture specs. | Unassigned |
| OQ-41 | Which mnemonics does the hardware use? | The architecture specs name `LOAD_LUT`, `LDR_MULT_REG`, `LDR_CYCLIC_MULT_REG` and `LDR_MULT_MASK_REG`. The repo standard is `UNIT.OP` with no underscore (`GLOSSARY.md`, Mnemonic): `LD.LUT`, `LD.MULT`, `LD.MULT.CYCLIC`, `LD.MASK`. | The specs adopt the repo names. | Unassigned |
| OQ-42 | Where do the AaQ architecture and microarchitecture specs disagree? | The store (merged into `ACTIVATE.QUANTIZE`, or a separate `ST.AAQ`); the operands; the format source (a CR, or the table); the activation encodings (0–6 or 1–7); inactive elements (NaN or 0); `reciprocal` and `rsqrt` at 0 and below; the `exp2` domain; the LUT metadata (46 or 75 bits); the LUT load operands; the opcode order. The emulator follows the architecture spec. | Bring the microarchitecture spec into line with the architecture spec. | Unassigned |
| OQ-43 | Is the dynamic exponent rule defined for 8-bit elements only? | Dynamic quantization is signed with `W = 8` (`ARCH-stage-aaq-str.md` §4.3.2.3), but the worked example uses `W = 6`. The rule scores truncation errors, while the quantizer it chooses for rounds to nearest. | Give a `W = 8` example and state which error the rule scores. | Unassigned |
| OQ-44 | Does row metadata carry `dynamic_static`? | The MULT architecture spec lists `Scale`, `dynamic_static` and `dynamic_exponent` (§3.2.1); the AaQ store (§4.3.3) and the cache unit (§6) write `scale` and `dynamic_exponent` only. MULT learns "dynamic" from its QF. The emulator stores no `dynamic_static` bit. | Drop it from the MULT spec. | Unassigned |
| OQ-45 | Is the element format a table property or an instruction operand? | The cache unit gives each table a 9-bit `format` (§5); the architecture specs take the format from a QF operand. | Drop the table `format` from the cache unit spec. | Cache unit owner |
| OQ-46 | What does an all-zero row quantize to? | The AaQ architecture spec treats every FP32 input as normalized (§4.3.2), zero included: a zero has exponent field 0, so an all-zero row gets scale 0 and each element the code of 1.0 × 2^-127, which reads back as 2^-127, not 0 (`ipu_isa.nx8.row_scale`, `encode_row`). A zero among nonzero elements underflows to the subnormal range and reads back as 0. The emulator follows the spec. | Special-case zero: an all-zero row stores code 0 in the clamp exponent (0.0). | Unassigned |
| OQ-47 | Is the emulator's 17-bit LUT entry encoding the hardware's? | No spec defines the entry format (OQ-38). `ipu_isa/lut.py` writes each entry as the top 17 bits of its FP32 pattern (sign, exponent, 8 mantissa bits) and `max_exp_num` as `range_exp + 127`; `lut_image` builds test rows with it. The emulator stores the bits exactly and evaluates with exact math, so the provisional encoding affects only what a test writes. | Replace the encoding in `ipu_isa/lut.py` when the format is published; until then it is provisional. | Unassigned |
| OQ-48 | What does an unsigned NX8 format do with a negative input? | Neither AaQ spec says (`ARCH-stage-aaq-str.md` §4.3.2, `MAS-stage-aaq-str.md`). The emulator encodes a negative element, -inf included, as 0 and sets `QUANT_SATURATION` (`ipu_isa.nx8.encode_row`). A negative element still takes part in choosing the row scale, by its magnitude (`row_scale`), so a large negative input can lower the precision of the positive elements. | State the rule in the AaQ architecture spec: clamp to 0, and say whether negative elements count toward the scale. | Architects |
