# Baseline digests of every assembled program

Part of [Epic E02: Safety nets before the refactors](00-epic.md) · ID E02-01 · Size S · Depends on: E01 (toolchain and lockfile pin) · Behaviour change: none

## Goal

Record the sha256 of the `.bin` and `.mem` output for every `.asm` program in the repo, and fail when any of them changes. This is the proof that E03 (package split, codec, mnemonic rename) and E05 (slot codec, assembly session, template API) leave the encoded programs byte-identical.

## Background

- 104 `.asm` files: 89 kernels (`src/tools/ipu-apps/src/ipu_apps/kernels/<family>/<kernel>/<kernel>.asm`), 12 MobileViT programs (`src/tools/ipu-apps/test/mobilevit/asm_packed_*.asm`), 3 VS Code fixtures (`vscode-ipu-asm/test/integration/fixture/kernels/`, `vscode-ipu-asm/test/corpus/`).
- `assemble_asm` (`asm_rules.bzl:3-21`) emits one format per genrule; `ipu_app` declares `assemble_<kernel>` for `.bin` only (`ipu_app.bzl:38-41`). The MobileViT programs have no assemble target.
- `lark_tree.assemble_to_bin_file` and `assemble_to_mem_file` (`ipu_as/lark_tree.py:196-226`) are the two library entry points. `kernel_registry/cases.py:59-67` `assemble_kernel` uses the `.bin` one.
- Four programs need a render context to assemble: `asm_packed_output_linear_{generic,generic_p4,silu,silu_p4}.asm` take `chunk_widths` (`test/mobilevit/test_full_layer_l4_packed.py:276-281`, same in `_l5_packed.py`). Their tests render with an unsandboxed `jinja2.Template`.
- Render-per-run kernels (`conv_universal_wide384`, `depthwise_conv_stride2_*`) render a different program per case (`kernels/convolutions/app.py:128-137`). Their standalone `.asm` assembles with `| default(...)` values. The per-case programs are covered by E02-07, which digests the binary each case actually runs.

## Implementation

1. Add `src/tools/ipu-apps/test/baselines/asm_corpus.py`. It lists the corpus as data:
   - every `.asm` matched by a glob over the three roots above;
   - for each program that needs a render context, the context its test uses today, copied as a literal (for example `{"chunk_widths": [128, 128, 64]}` for each `k` the L4/L5 tests use). One entry per (path, context) pair.
2. Add `src/tools/ipu-apps/test/baselines/asm_digests.json`, keyed by `"<repo-relative path>"` or `"<path>?<context-json>"`:
   ```json
   {"src/tools/ipu-apps/src/ipu_apps/kernels/softmax/softmax_rows/softmax_rows.asm":
      {"bin_sha256": "…", "mem_sha256": "…", "words": 212}}
   ```
3. Add `py_pytest_test(name = "test_asm_digests")` in `src/tools/ipu-apps/BUILD.bazel` with every corpus `.asm` as `data`. For each entry it renders (with the context, through the same renderer the test uses today), assembles in-process to `.bin` and `.mem` bytes, and compares digests. On mismatch it prints the path, both digests and the first differing word index. Use `shard_count` so the target stays under 60 s wall time on CI (Q71).
4. Add `py_binary(name = "update_asm_digests")`: `bazel run //src/tools/ipu-apps:update_asm_digests` rewrites the JSON from the current tree. E02-09 folds it into the single update command.
5. The test also fails when a corpus `.asm` file exists that the manifest does not list, or the manifest lists a path that no longer exists. A new kernel therefore adds its digest in its own PR.

## Tests

- [ ] `test_asm_digests` passes on the base commit.
- [ ] Planted change: editing one immediate in a copy of one kernel makes the test fail and names the file (test of the harness, using a temp corpus).
- [ ] A new `.asm` file not in the manifest fails with a message that names the update command.
- [ ] `bazel test //...` runtime grows by less than 60 s.

## Acceptance Criteria

- [ ] Every `.asm` under the three roots, and every render context used by today's tests, has a `.bin` and a `.mem` digest in the manifest.
- [ ] The manifest is regenerated by one `bazel run` command.
- [ ] The test is part of the default `bazel test //...` tier.

## Risks

- Programs that assemble differently depending on import order or global label state (`label.ipu_labels`, reset in `lark_tree.parse`) could make the test order-dependent. Assemble each entry in a fresh label state; E05 removes the global.
- MobileViT render contexts are copied, not imported, from manual tests (`ipu_app.bzl:178-185` tags `test_full_*` manual). If those tests change their context, the manifest entry must change in the same PR; note this in the corpus file.
