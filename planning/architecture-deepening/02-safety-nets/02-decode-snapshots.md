# Snapshot decoded field names, disassembly text and enum descriptors

Part of [Epic E02: Safety nets before the refactors](00-epic.md) · ID E02-02 · Size S · Depends on: E02-01 · Behaviour change: none

## Goal

Pin three things that are wire format but are derived from Python class names today:

1. the field names and widths of a decoded instruction word, which the emulator, test fixtures and debugger traces key on;
2. the disassembly text of every word in the E02-01 corpus, which the debugger CLI and pipeline view show;
3. the enum descriptors (name to value tables) that feed the SV package and the VS Code data.

E03 moves decoding into `ipu_isa` with an explicit field-name table (Q69), and E05 deletes the nine `Inst` subclasses. Both must leave these snapshots unchanged.

## Background

- `CompoundInst.get_fields()` (`ipu_as/compound_inst.py:145-178`) builds names such as `lr_inst_0_token_0_lr_inst_opcode` from `camel_case_to_snake_case(inst_type.__name__)` and `token_type.__name__`. It returns 2-tuples `(name, bits)`, LSB first.
- The emulator rebuilds the operand part of those names from its own tables: `_TYPE_FIELD_SUFFIX` (`ipu_emu/ipu.py:213-230`) and `_SLOT_FIELD_PREFIX` (`ipu.py:233-244`). `_TYPE_FIELD_SUFFIX` has no entry for `LrOrReshapeMaskImmediate`; it works only because that type is never a union field's canonical type.
- `CompoundInst.decode(word)` (`compound_inst.py:124-133`) produces the disassembly text. `debug_cli.disassemble_at` (`ipu_emu/debug_cli.py:361-380`) and `debug_pipeline.stage_operations` (`ipu_emu/debug_pipeline.py:15-25`) re-encode a decoded dict and call it.
- `EnumToken.get_all_enum_descriptors()` (`ipu_as/ipu_token.py:134`) feeds `gen_codegen._enum_descriptors_for_templates` (`gen_codegen.py:336-358`).
- The two MobileViT measurement fixtures hard-code field-name strings (`test/mobilevit/fixture_packed_l4_measure.py`, `fixture_packed_l5_measure.py`).

## Implementation

1. Add `src/tools/ipu-as-py/test/baselines/` with three checked-in files, all plain text so a review shows the diff:
   - `word_fields.json`: the `get_fields()` list as `[name, bits]` pairs, LSB first, plus the total width (186 today).
   - `emulator_field_maps.json`: for every `(slot, instruction)`, the operand-name to field-name map the emulator builds (`_build_all_instruction_field_maps`), and the opcode field per slot instance. This pins the keys the emulator dispatch reads.
   - `enum_descriptors.json`: every enum descriptor name with its ordered member names and values.
2. Add `src/tools/ipu-apps/test/baselines/disassembly/` with one `.txt` file per E02-01 corpus entry: one line per word, `"<index>: <CompoundInst.decode(word)>"`. Text, not a digest, so a mnemonic rename (E03) or a formatting change shows as a readable diff.
3. Add two tests:
   - `//src/tools/ipu-as-py:test_decode_snapshots` compares items 1 (three JSON files) against the current code;
   - `//src/tools/ipu-apps:test_disassembly_snapshots` decodes every assembled word of the E02-01 corpus and compares item 2. It reuses the E02-01 corpus list and assembles once per entry.
4. Add `update_decode_snapshots` and `update_disassembly_snapshots` `py_binary` targets that rewrite the files.

## Tests

- [ ] Both tests pass on the base commit.
- [ ] Renaming a token class in a monkeypatched copy changes `word_fields.json` output (proves the snapshot catches class-name drift today).
- [ ] Every corpus entry has a disassembly file; a missing or extra file fails the test.

## Acceptance Criteria

- [ ] Field names, emulator field maps, enum descriptors and disassembly text for the whole corpus are pinned and regenerated by `bazel run` commands.
- [ ] Both tests are in the default tier and together add less than 30 s.

## Risks

- The disassembly files are large in total (one line per word, about 100 programs). Keep one file per program so a diff stays local to the programs a PR touches.
- E03's mnemonic rename (Q45) changes the disassembly text by design. That PR regenerates these files and the reviewer checks that only mnemonics changed.
