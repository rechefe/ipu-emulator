# One source for number syntax and slot-fill rules

Part of [Epic: Debugger, generators and editor](00-epic.md) · ID E08-21 · Size M · Depends on: E08-15 (generator in `ipu_gen`) · Behaviour change: yes (the editor accepts signed hex, binary and octal literals exactly when the assembler does, and flags an over-full word the same way the assembler does)

## Goal

Two language rules the extension re-implements by hand, and gets wrong, come from the assembler's own data in `isa.json`:

- which number literals are valid;
- how a word's instructions fill its slots.

This is the cheap first step before the full language service (E08-22). It also fixes the editor for Marketplace users who have no checkout, since they only ever see the bundled `isa.json`.

## Background

- **Number syntax.**
  - `language.js:392-402` (`accepts`) matches `^[+-]?(0[xX]…|0[bB]…|0[oO]…|\d+)$`, then calls `Number(v.replace(/_/g, ''))`.
  - `Number("-0x10")` is `NaN`, so the editor rejects signed hex, binary and octal that the assembler accepts through Python `int(v, 0)`.
  - `Number` also loses precision above 2^53.
- **Slot fill.**
  - `language.js:345-359` (`fits`) claims to mirror `CompoundInst._fill_instructions`, but differs. In JS, any mnemonic with more than one form (or no slot) takes the first free slot in `slotOrder`. In Python, only `nop` is a wildcard (`compound_inst.py:36`); every other mnemonic must take a slot of its own kind.
  - JS therefore accepts some over-full words that the assembler rejects.
- `isa.json` is generated by `gen_vscode` (`ipu_gen/vscode_data.py` after E08-15) and has no `schemaVersion`.

## Implementation

1. In `vscode_data.py`, add to `isa.json`:
   - `"schemaVersion": 1`, an integer (L40);
   - `"numberPattern"`: the regex the assembler's number tokens accept, derived from the Python parser's accepted forms and checked by a Python test that runs every corpus literal through both;
   - `"slotFill": {"order": [...], "wildcards": ["nop"], "rule": "own-kind"}`, derived from the codec slot order and `CompoundInst` (after E05-02, from `ipu_as.encode`).
2. In `language.js`:
   - parse numbers with `BigInt` plus a sign and underscore removal, and compare against the domain using `BigInt`;
   - `fits()` follows `slotFill`: wildcards take the first free slot in `order`, and every other mnemonic needs a free slot of its own kind.
3. A bundled `isa.json` without `schemaVersion` is treated as version 0, with the old behaviour. That keeps an older checkout working (E08-25 handles source selection).
