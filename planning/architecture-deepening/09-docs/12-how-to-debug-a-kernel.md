# How-to: debug a kernel

Part of [Epic E09: Documentation restructure](00-epic.md) · ID E09-12 · Size M · Depends on: E09-06, E08 (`ipu_debug`: DebugSession core, CLI and TUI adapters; Cycle Inspector page phase 1), E06 (runner owns debug and profile) · Behaviour change: none

## Goal

A kernel author whose kernel gives the wrong answer, faults, or is slow finds
the debugging workflow on one page: open the debugger on a case, step,
break, inspect registers and XMEM, read a fault, profile.

## Background

- `debugging.md` is 681 lines. Most of it (`:97-529`) documents the commands
  of the deprecated line debugger (`:44-57` calls it deprecated). The TUI
  (`bazel run --config=debug <target>`) is covered in `:5-43`. `:530-562`
  shows `run_with_debug` from Python.
- `debugging.md:79` documents `break_nop`, which is not a mnemonic (E09-01).
- `README.md:44-60` repeats the TUI key bindings.
- E08 builds `ipu_debug` with one DebugSession core and CLI and TUI adapters,
  splits the TUI per pane, and adds a Cycle Inspector docs page (phase 1:
  traces recorded by Bazel from the reference-model trace writer; Q51, Q55).
- E06: the kernel runner owns `--debug` and profiling (Q80, `--debug` on
  `bazel run`).
- E04: faults F-1 to F-9 halt and record a code and PC (Q52, Q59). A debugging
  page must show how to read them.
- Q37 asks that debugging is part of the docs restructure.

## Implementation

1. Write `how-to/debug-a-kernel.md` with `anthropic-skills:technical-writing`.
   Organise by symptom:
   - Wrong output: run one case in the debugger, set a breakpoint (`BREAK` in
     source, or a PC breakpoint), step, inspect registers and XMEM in the
     element format, compare with the reference.
   - A fault halted the run: read the fault code and PC, look the code up in
     the fault list (`requirements/faults.md`).
   - Too slow: cycle count, MAC utilisation, the alias profiler (moved here
     from E09-10).
   - Look at a recorded run without a terminal: link the Cycle Inspector page
     (E08).
2. Key bindings and commands go in a table generated by E08 from the
   adapter's key map, if E08 exposes one. Otherwise one hand table here, and
   `README.md` links it instead of repeating it. Open question: does E08 expose
   the key map as data?
3. Drop the deprecated line debugger. If E08 keeps the Python API, document it
   in the reference-model API page (E09-16), not here.
4. Delete `debugging.md`; fix inbound links.
