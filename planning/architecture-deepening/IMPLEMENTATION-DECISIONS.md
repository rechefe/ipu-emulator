# Implementation decisions

The issue drafts left some questions open. To keep implementation moving, these defaults apply. Each one can be overridden in PR review; an override becomes a follow-up issue.

The user decided the program-level questions in the grilling session. They are recorded in [README.md](README.md#decision-record) and in `docs/adr/`.

## Repository layout and packaging

| Question | Default | Raised in |
|---|---|---|
| Where do kernels live? | Top-level `kernels/<family>/<name>/` (one Bazel package per kernel: `//kernels/<family>/<name>`). The Python support code is `ipu_harness` under `src/tools/ipu-harness/`. Kernels need no Python package. | E06 epic, E06-01, E06-17 |
| Are mnemonic aliases kept after the rename? | No. All in-repo sources are renamed in the same change, and the old names are rejected with a hint that names the new mnemonic. | E03-19, E05-16 |
| Can an EMULATOR instruction sit inside a HARDWARE slot? | No. The schema check rejects it. `HALT` is a hardware instruction, so no case needs it. | E03-07 |
| Which slots warn as "simulation-only" after the tags land? | Only ACC_STORE. `SlotInfo.debug_only` marks it, alongside its EMULATOR tag. The assembler warning, `emulator_only_instructions` (kernel tests expect `DebugOnlyInstructionWarning` from it), the generated docs note, the editor's `hardware` flag, the alias spec's `hardware_only` and the debugger's `*` labels read `debug_only`, so BREAK (also EMULATOR) changes none of them. The hardware views (`word_bits(Tag.HARDWARE)`, E03-22 SV, E03-23 RTL docs, E05-15 `--target hardware`) read the tag. E03-23 and E05-15 decide whether the user-facing notes move to the tag. | E03-07, E03-23, E05-15 |
| Hardware binaries | `--target hardware` writes `<name>.hw.bin` with no header. | E05-15 |
| `check --json` schema files | `vscode-ipu-asm/schema/` | E05-08 |
| Template parameters | Declared in `kernel.toml [params]`. A standalone template may use an `ipu:params` header comment. | E05-09 |
| `--abi` input | A `kernel.toml` path. Only its `[abi]` table is read. | E05-13 |
| How are the dependencies between packages enforced? | One table, `tools/import_graph.toml`, lists the first-party packages each package may import. `//tools:test_import_graph` reads every source under `src/tools/*/src/<package>/` and fails on any other first-party import, including function-level imports and literal `importlib.import_module` calls. A package with sources and no row fails the test, and so does an import of an `ipu_*` package whose `:py_sources` are not in the test's data. Rows are per top-level package; "nothing imports X except Y" is expressed by listing X only in Y's row. Later issues add rows (E06-01, E08-03, E08-13) or delete the edges marked temporary (`ipu_emu` → `ipu_as`, planned for E03-18, went in E03-16 once the word codec removed its last use; `ipu_as` → `ipu_gen` in E08-14). E06-01 extended the schema: dotted subpackage keys (the longest key wins; `ipu_kernels.reference` may import only `ipu_isa`, stricter than "not `ipu_emu`" because the framework and the rest of `ipu_kernels` reach the emulator) and a `[deferred]` table of modules a key may import only inside a function (`torch` from `ipu_harness`). `ipu_harness` never imports `ipu_kernels`, not even inside a function (Q62); E06-09 and E06-16 load kernel-side modules with `importlib.import_module` on a name read from registry data, which is plugin loading, not an edge (the test sees only literal names). No issue adds a separate check. `//src/tools/ipu-isa:test_purity` stays as the run-time check that `ipu_isa` imports with only its own library on the path. | E03-02, E03-18, E06-01, E08-03, E08-13 |

## ISA and emulator

| Question | Default | Raised in |
|---|---|---|
| XMEM row count per format | The byte address space stays the same (512 MiB, allocated lazily). Addressable rows are that space divided by the row width. The hardware row limit is an open question in `requirements/open-questions.md`. | E03-13 |
| IMEM depth | Stays a constant in `ipu_isa`. Making it a run-time parameter is an open question. | E03-12 |
| What `HALT` does | Enters `HALTED` and reports kernel done. Fetching past the program end is fault F-2. | E03-20 |
| CR1 as an element scalar | CR0 and CR1 are hardware constants for 0 and 1. As an element scalar, CR1 reads as the encoding of 1.0 in the active format, so `MULT.VE … CR1` stays an identity multiply. As an LR or integer operand it is the integer 1. This is documented in the ISA reference. | E04-28 |
| Disabled faults | Only F-1 (the slot runs as `NOP`) and F-9 (the run continues) may be disabled. Disabling any other fault is a configuration error, until OQ-2 is answered. | E04-22 |
| Does a MULT product overflow set the accumulator overflow flag? | Yes. It sets the same arithmetic-event flag. | E04-23 |
| `pad_mode` that needs float lanes under an integer format | Configuration error. | E04-19 |
| R_CYCLIC alignment check | Fault F-4. | E04-19 |
| F-6 / F-7 | F-6 covers addresses beyond the XMEM address space. F-7 is never raised until tables exist. | E04-19 |
| Matmul benchmark kernel | `matmul_720x240_x128`, the largest standard case. Overridden for E04-02: it uses `matmul_384x192_x128`, because 720x240 takes about 22 s a run and `bench_emulator -- --quick` must finish in 30 s. E01-14's `kernel/*` keeps 720x240. | E04-02, E01-14 |
| Where the element codec lives | `ipu_isa.formats`, so the harness packs data without importing the emulator. | E04-13 |
| JSON schema validation | `jsonschema` as a test-only dependency. | E04-29 |
| Fault model | `EmulatorFault(fault: FaultId, pc, detail)`; handlers raise it through `Ipu._fault` with the current PC (every slot but COND runs before the PC moves). `Cycle.step`/`retire`/`evaluate_break` record `IpuState.halt = HaltRecord("fault", pc, fault)` and re-raise; an `XMemBoundsError` (new: `EmulatorError` and `ValueError`, raised by `XMem`'s own bounds check, a configuration error outside a cycle) becomes F-6 there. F-1 is checked once per cached schedule (`schedule_word`): an undefined opcode (negative codes too, which indexed from the end before), and every operand code that `ipu_isa.faults.reserved_operand_codes` reserves or that is past its operand type's width (`SlotPlan.operand_checks`; union columns are wider than some types, e.g. SET `src` in the 8-bit ADDBI column); the handler checks for `MultStageReg`, LDR `dest` and INCR_MOD_POW2 `k` stay as a second line. `program_length` defaults to all of IMEM for a state whose IMEM is written directly; `load_program` sets it. Both run loops run while `halt is None`, so any PC past the program, IMEM included, is fetched and faults F-2. Deviation: `is_halted` is `halt is not None` *or* PC past IMEM, because the debugger's quit (`DebugSession.halt`, lane A's) still moves the PC there (`run_with_debug` stops on it after the callback); `_begin_run` clears `halt`, so a rerun after setting the PC works as before; a rerun that leaves the PC past IMEM (after a HALT) now faults F-2 there, where it returned 0 cycles. Fault priority within one word (IPU-FLT-8: e.g. a bad row checked before a bad cyclic index, F-3 before a handler's F-1) is E04-20's, with precision. Open questions kept as `EmulatorError`, not faults: `pad_mode` under integer lanes, wide-mode R_CYCLIC alignment and QUANTIZE outside INT8 (OQ-20), and an ACC.STRIDE whose start plus element count overruns R_ACC (stage-accumulator 6.8 leaves it undefined; it was a `struct.error`). F-9 is E04-21's. | E04-19 |
| Cycle limit and run bookkeeping | `IpuState.cycle_limit` (`DEFAULT_CYCLE_LIMIT = 1_000_000` beside it in `ipu_state`; `emulator.DEFAULT_MAX_CYCLES` is the same constant, the one default of every runner and the apps' harness); 0 disables the check. The helper is `ipu_emu.run_clock.RunClock` (`begin_run(reset_stats=)`, `admit()`, `count_cycle()`, `end_run()`), not the spec's `run_control.RunControl`: that name is already the debugger's seam. `admit()` before each cycle faults F-9 at the PC of the word that would run, recording the halt, so `raise_on_fault=False` returns on it too; `end_run()` in a `finally` is the one place `total_cycles` is written (accumulated over earlier runs when `reset_stats=False`). A runner's `max_cycles` sets `state.cycle_limit`, which stays after the run. The lockstep test helpers (`emu_support.run_both`, `timing_probes`) keep their own loop guards; the apps' post-run `is_halted` checks no longer describe the limit. | E04-21 |
| Conformance data | `src/tools/ipu-isa/conformance/` (programs plus expected traces). | E04-31 |
| Unknown `IPU_EMU_PROTOTYPING` value | Raises `ValueError`. | E00-04 |

## Kernels and harness

| Question | Default | Raised in |
|---|---|---|
| LR presets | `[abi]` accepts LR targets (`i = "LR3"`) as well as CR targets. | E06-06 |
| Assembly with case values | `ipu_harness.assembly.assemble(plan, cache=None, *, asm_lib=None)` replaces the spec's `assemble(plan, session) -> Program`: it returns E05's `AssemblyResult` (words, labels, rendered text; no source map, since E05's session has none: the runner reports positions as rendered lines, as `check_cr_reads` does, and E06-11 confirms `rendered` plus `symbols` is enough) and builds the session itself. The template values are every parameter (floats too), `format` and `shapes` (each tensor's shape as a list), declared to the render as a `ParamSpec` built from `[params]` (`kernel.toml` is the declaration; an `ipu:params` header is not read; `ipu_as.template` names a caller's float and dict types in its errors), with the `[abi]` names as the `cr`/`lr` namespaces (`template_names`). The cache is an `AssemblyCache` the caller holds (the runner, one per run; unbounded, so not longer), keyed by the SHA-256 of the *rendered* program: rendering is cheap and encoding is not, so two cases that render alike share an assembly whatever their values, an included file's change shows in the render (E05's own cache refuses a search path for that reason), and a hit raises the program's warnings again. The search path is the kernel folder and its family folder, then `asm_lib` when the caller passes it (the runner's Bazel data, E06-11/E06-13); a given `asm_lib` that is not there is an error. The Bazel `assemble_<name>` target and its E02-digest test come with E06-13's `ipu_kernel()`. | E06-07 |
| Reference loading | `ipu_harness.reference.load_reference(manifest, *, shared="ipu_kernels.reference.ops")`: `[golden] reference = "file.py:fn"` loads the kernel's file by path (the loader already fills in `reference.py:reference` when the file exists), `op = "<name>"` imports the shared module by name (Q62); none gives None (only `expected` files check the kernel); a file or op that does not load or is no function is a `PlanError` at `golden.reference`/`golden.op`. `evaluate(fn, inputs, params)` imports torch when it runs (mypy.ini ignores torch's missing stubs). Kernel-side files are loaded through `ipu_harness._plugins` (by path, cached by content; by name), which packing uses too. Part 2: `torch==2.14.1+cpu` is in `ipu-kernels`' `dev` extra, from PyTorch's CPU index (`[tool.uv.sources]` for the lock, `--extra-index-url` in `pip.parse`), so the lock never pulls PyPI's CUDA wheel; only `//src/tools/ipu-kernels:test_reference_ops` depends on it today (E06-13 adds the kernel tests), and `ipu_harness`' own tests stay torch-free. `ipu_kernels.reference.ops` holds `matmul`, `silu`, `softmax` and `layernorm` (no eps, rsqrt of a zero variance is 0, along `dim`). A shared op names its inputs (`x`, `a`, `b`, `gamma`, `beta`), returns its one output as `y` (so a kernel that uses `op` has exactly one output, `y`), and ignores case parameters it does not read; an op that reduces along an axis (`softmax`, `layernorm`) takes `dim` with no default, which the kernel declares in `[params]`, because layouts differ (normalize keeps channels on axis 0). The datapath mirrors (`reference/datapath.py`, step 4) move with attention in E07, where the rule pairing a mirror with an `ops` reference lands. The default tier fetches the ~200 MB wheel once on a cold cache (`test_reference_ops`); the CI cold-cache time is to be measured on the first CI run. `evaluate` is tested end to end there, through `load_reference` of an `op` kernel. The runner (E06-11) calls `load_reference` only when it compares against a reference, so an `expected`-only run of an `op` kernel needs no torch. | E06-09 |
| Golden comparison | `ipu_harness.tolerance`: the spec's six tiers (`EXACT`, `FP32_ORDER`, `FP32_LONG`, `TRANSCENDENT`, `INT8_LSB`, `FP8_ULP`), provisional until E07-03 measures them. `[golden] tolerance` maps a format to a tier name (unknown: load error) or to `{ tier, rtol?, atol?, ulps?, why }` (the `why` required); `GoldenDecl.tolerance` holds `Tier`s keyed by the format an output is stored in, so an accumulator format (FP32, INT32) may be named too and an accumulator output takes its accumulator format's tier (`tier_for(plan, tensor)`); a format it does not name is compared at `EXACT`. An override may set only what `compare` reads for that format (`ulps` only for an 8-bit float, and then not `rtol`/`atol`). `ipu_harness.compare`: `expected_for(case, plan, ref_out)` takes the case's `expected` file over the reference and rounds either once, with saturation, to the output's stored format (`packing.stored_format`: the element format, or the accumulator's); the reference must make exactly the declared outputs, and an expected value must be finite; an output with neither has no golden, and the runner (E06-11) makes that a failure under `bazel test` ("no golden") and a smoke run under `bazel run`. `compare(output, got, want, tier, fmt)` (the spec's `compare(got, want, tier)` plus the name and format it reports and needs): an element passes when `|got - want| <= atol + rtol * |want|`, or, for a tier with `ulps` in an 8-bit float format, when both are codes of the format at most `ulps` codes apart (`_codec.codes`; a value that is no code, NaN or infinity fails, `max_ulps = -1`); `Comparison` adds `max_ulps` and `describe()`, and names the worst element (the furthest out of tolerance, or the largest difference when all pass). | E06-10 |
| `kernel.toml` readers and loader scope | `ipu_harness.manifest.load_manifest` is the reader; the one other is `ipu-as assemble --abi`, which reads only the `[abi]` table (E05-13; `ipu_as` cannot import `ipu_harness`), and a test allows exactly these two. The loader checks names, domains and paths; E06-03 evaluates shapes; E06-10 checks tolerance tier names and adds the per-kernel table form (settled on E06-10's and the epic's spellings, `EXACT`, `FP8_ULP`, ...); E06-08 adds an input's `range` key; E06-11 adds `[benchmark]`. A registry entry's `params` are fixed values (the param's only choice, and its value in every template case) and its `formats` a subset; errors name the entry's source. `BYTE_UNIT_KERNELS` is keyed `family/name`. | E06-02 |
| `plan_case` details | `PlanError` is an `ipu_emu.errors.ConfigurationError` (Q59), and so is `ManifestError`. `plan_case(..., case=CaseDecl)` takes the case itself, so a sweep's expanded cases pass their base. `CasePlan.derived` holds every `[derived]` value; a value that does not evaluate is an error, never skipped. The shape grammar (`ipu_harness.expressions`, checked at load and evaluated per case) adds `/` (exact; whole result or inside `ceil`) and unary minus to the spec's list; `ceil` takes 1 argument, `min`/`max` at least 2. `check_params` returns the complete params and the formats whose element scalars accept them (E06-16). Exactness of element scalars uses the emulator's public FP8 codec until E04-13. The "later stages take only a `CasePlan`" test lives in E06-04, E06-05, E06-07 and E06-11; a source scan keeps the checks out of every module but the entry points. | E06-03 |
| Region placement details | `place(plan, row_counts=None)`: a tensor packing (E06-05) gives no count for takes `default_rows` (one row per 128 elements of the last dimension per index of the others, times the accumulator stride for a `store = "accumulator"` output); a given count is the rows as stored, stride included. `row_counts` naming no tensor, or below 1, is a `ValueError` (a caller bug, not configuration). `Placement` also carries `capacity` (`ipu_isa.formats.addressable_rows`). Placement only reserves rows; the runner writes a scratch region's `fill` (E06-11). The `projections` layout guard uses today's XMEM shapes with `default_rows`; E06-05/E07-02 re-run it with packing's counts. | E06-04 |
| Cases and inputs | `Case` adds `decl` (its `CaseDecl`, for `plan_case(case=)`) to the spec's fields; `formats` is the case's limit, else the kernel's. A sweep's point is named `<case>[k=v,...]` with TOML spellings, axes in declaration order. `rng(kernel, case, tensor)` seeds from CRC-32 of `"<manifest.name>/<case name>/<tensor>"`; a case generator gets the stream for tensor `generator` (a reserved name). A generator is named `"gen.py:make"` (the spec's `"gen:make"` with the file's suffix, as every `file.py:fn` reference). Default values: uniform `[-1, 1]` (float formats) or integers over an integer format's whole range, or the input's `range` (`[lo, hi]` for every kernel format, or per format), which the loader checks lies in the format's limits and, for an integer format, holds an integer. Every input is rounded to the format, to nearest and saturating (`ipu_harness._codec`; FP8 through the emulator's codec until E04-13). **User data follows E06-10's rule** (coordinator's call, the owner may veto on the PR): a `.npy` (case `inputs` or `--input`) or a generator's tensor is rounded, not rejected, and `inputs_for` returns how many values rounding changed per tensor (`CaseInputs.rounded`) for the report; only a non-finite value, a non-int/float dtype or a wrong shape is an error. Errors from a case's own files and generator are `PlanError`s keyed `cases.<name>.inputs.<tensor>` / `.generator` (a generator that fails to load or raises included); `--input` errors are `ConfigurationError`s naming the path. | E06-08 |
| Routing registry | `ipu_harness.registry`: `Registry.load(root, *, families=, package="ipu_kernels")` reads `<root>/<family>/<name>/kernel.toml` (TOML only; a missing root is an error); layer adapters are `LAYER_ADAPTERS` of `<package>.<family>.layers`, imported with `importlib.import_module` on first `from_layer` (Q62 plugin loading; a family without the module has none; a failure is kept and raised again). `default_registry()` loads `kernel_tree()`: `$RUNFILES_DIR/_main/kernels` under Bazel (data `//kernels:tree`), else the checkout's. `[kernel] cost` is a number (negative prefers a kernel, as `sample_descriptors_separable`'s -1 today) or a shape-grammar expression over integer params and derived values; `check_params` returns `derived` for it. **Ties:** two accepting kernels at the same lowest cost on a query are a `ConfigurationError` at `resolve` (the spec says at load, but a tie between accepting kernels exists only per query, so it is raised there; `ipu_apps` broke them by name, so E07 gives tied pairs such as `maxpool2d_nms7`/`nms9` and `conv1x1`/`conv3x3_relu` distinct costs where their domains overlap); equal costs are fine at load. A cost that does not evaluate propagates. `resolve(op, /, *, format=None, **params)` (`format` is a reserved parameter name); a refusal quotes `PlanError.reason`. **Output:** `query`'s arguments are unchanged (comma tuples, `--sweep`, `--json`), and `Verdict.to_dict` keeps `ipu_apps`' keys so one tool reads both, with kernel-query content: `reason` is the routing decision, `app` the kernel name, `use` its label (`//kernels/<family>/<name>`; E06-17 entries get theirs), `kwargs` its params, `shapes` None, `notes` its formats; `describe()` likewise. E07 states per family how an `ipu_apps` shape query maps to kernel params (or goes through the layer adapters) when it checks the two tools agree. `//kernels:query` aliases `//src/tools/ipu-harness:query`. `//kernels:manifest` needs `ipu_kernel()`'s target file, so it lands with E06-13 (a test bullet there). The `ipu_apps` registry tests (`_ADAPTERS.pop`, `sys.path`, `sys.modules`) test the old registry and go with it in E07. registry.toml entries are E06-17's. | E06-16 |
| Packing | `ipu_harness.packing`: `pack(tensor, a, plan)` checks the exact planned shape (a `PlanError` keyed `<section>.<name>.shape` naming both shapes), lays the tensor out with its transform and encodes with `ipu_harness._codec.encode` (round to nearest, saturating); `unpack` checks the region's byte size and decodes, an `accumulator` output in the format's accumulator format (`FormatInfo.accumulator`). Every per-format branch is in `_codec` (the E03 element codec arrives with E04-13; until then FP8 uses the emulator's). `pack = "<name>"` resolves to the kernel folder's `pack.py` (by file), then `ipu_kernels.<family>.pack`, then `ipu_kernels.pack` (by name, Q62); a transform is any object with `rows`/`to_rows`/`from_rows`. Shared set in `ipu_kernels.pack`: `channel_major` (`(..., groups, channels, width)` to a row per (channel, group); the projections' `_load_data`), `output_major_weights` (the row-major default under its name; `_load_weights`) and `chunk_interleaved` (`(channels, rows, cols)`, cols dividing 128; the convolutions' `pack_input_chunked`), each held byte for byte to the loader it replaces; a shape a transform cannot lay out is its `ValueError`, reported as a `PlanError` at `<section>.<name>.pack`. `stored_rows(tensor, plan)` (the transform's rows, times the accumulator stride for an `accumulator` output) is what the runner passes `place` as row counts, and `stored_format` what E06-10 rounds a golden to; with them the projections' logical shapes place at today's bases (the E06-04 guard re-run with packing's counts). A kernel's `pack.py` is executed once per file version. `ipu_kernels` may import `ipu_isa` (import graph) for the lanes. | E06-05 |
| Register programming | `ipu_harness.abi`: `register_writes(plan, placement)` returns `RegisterWrite(register, value, source)` (the spec's `CrWrite`, renamed because `[abi]` also presets LRs, E06-02) in `[abi]` order, then the default dstructure (`encode_dstructure(valid_elements=128)`) in CR15 unless bound; values are raw 32-bit register bits (a negative integer as two's complement); a value outside [-2^31, 2^32) is a `PlanError` keyed `abi.<name>`. Derived CR values are `[derived]` expressions (option a; constants such as `-1` and `126` are expressions too), and LR presets are `[abi]` entries. A `str` parameter cannot be bound (load error). `template_names(manifest)` gives `{"cr": {...}, "lr": {...}}` for E06-07. **Partial:** `apply(state, writes)` writes through `IpuState.regfile.set_scalar(bank, index, value)`; E04-30's reference-model `write_register` replaces it when it lands. CR15's index comes from `ipu_emu.ipu_config` (the emulator's convention; `ipu_isa` has no constant for it). `check_cr_reads(manifest, rendered)` parses the rendered program (E06-07's `AssemblyResult.rendered`) and fails a read of a CR other than CR0, CR1, CR15 and the bound ones, found by operand type (`ipu_isa.view`; a label spelled `cr9` is no read). It names the **rendered** line and quotes its text: the program file's line when the program has no template layer; mapping through includes and loops would need a source-map method on E05's session, which is not this issue's. For E07: a kernel that changes CR15 between stages (the mobilevit tests) needs a binding per stage (E06-14), and a memory kernel whose `crs` sets CR15 loses that value to `MemoryApp`'s dstructure today, while `[abi]` keeps it; E07 checks none does. | E06-06 |
| `isa.json` number and slot-fill data | `numberPattern` is `ipu_as.ipu_token.NUMBER_PATTERN`, a hand-written regex (in syntax Python `re` and JS `RegExp` read alike) held to `int(v, 0)` by `test_isa_data` on every string of up to 4 characters over the literal alphabet, 20000 seeded longer ones and every corpus token; "derived" means that test. `slotFill` adds `kinds` (mnemonic -> slot kind: the slot of its real form in the generator's view, a pseudo-instruction's the slot it expands into; the same slot `CompoundInst` fills) to the spec's shape. `slotOrder` stays beside `slotFill.order` so version-0 readers keep working. Operand bounds stay JSON numbers (exact while ranges stay within 2^53). | E08-21 |
| Extension agreement and waits | Both directions are checked by `test/verdicts.js` (the editor's verdict, `test/verdict.js`, on the corpus, `mangle.mutations` of it and `test/corpus/negative/`) and `//vscode-ipu-asm:check_verdicts`, which judges each text with `ipu_as.diagnostics.check` (what `ipu-as check --json` prints) and fails on a disagreement not in `test/corpus/negative/allowed-gaps.json`, or a listed gap that no longer occurs; `agreement.js` stays the TextMate tokenizer test. | Derived values | A `[derived]` table of arithmetic expressions over params (E06-03's grammar), constants included; no `module:fn` hook was needed for any CR value so far (E06-06, "Register programming"). | E06-06 |
