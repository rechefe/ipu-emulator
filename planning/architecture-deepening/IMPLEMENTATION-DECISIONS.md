# Implementation decisions

The issue drafts left some questions open. To keep implementation moving, these defaults apply. Each one can be overridden in PR review; an override becomes a follow-up issue.

The user decided the program-level questions in the grilling session. They are recorded in [README.md](README.md#decision-record) and in `docs/adr/`.

## Repository layout and packaging

| Question | Default | Raised in |
|---|---|---|
| Where do kernels live? | Top-level `kernels/<family>/<name>/` (one Bazel package per kernel: `//kernels/<family>/<name>`). The Python support code is `ipu_harness` under `src/tools/ipu-harness/`. Kernels need no Python package. | E06 epic, E06-01, E06-17 |
| Are mnemonic aliases kept after the rename? | No. All in-repo sources are renamed in the same change, and the old names are rejected with a hint that names the new mnemonic. | E03-19, E05-16 |
| Can an EMULATOR instruction sit inside a HARDWARE slot? | No. The schema check rejects it. `HALT` is a hardware instruction, so no case needs it. | E03-07 |
| Which slots warn as "simulation-only" after the tags land? | Only ACC_STORE. `SlotInfo.debug_only` marks it, alongside its EMULATOR tag. The assembler warning, `emulator_only_instructions` (kernel tests expect `DebugOnlyInstructionWarning` from it), the generated docs note, the editor's `hardware` flag, the alias spec's `hardware_only` and the debugger's `*` labels read `debug_only`, so BREAK (also EMULATOR) changes none of them. The hardware views (`word_bits(Tag.HARDWARE)`, E03-22 SV, E03-23 RTL docs, E05-15 `--target hardware`) read the tag. E03-23 and E05-15 decide whether the user-facing notes move to the tag. | E03-07, E03-23, E05-15 |
| Hardware binaries | `--target hardware` writes `<name>.hw.bin` with no header. | E05-15 |
| `check --json` schema files | `vscode-ipu-asm/schema/` | E05-08 |
| Template parameters | Declared in `kernel.toml [params]`. A standalone template may use an `ipu:params` header comment. | E05-09 |
| `--abi` input | A `kernel.toml` path. Only its `[abi]` table is read. | E05-13 |
| How are the dependencies between packages enforced? | One table, `tools/import_graph.toml`, lists the first-party packages each package may import. `//tools:test_import_graph` reads every source under `src/tools/*/src/<package>/` and fails on any other first-party import, including function-level imports and literal `importlib.import_module` calls. A package with sources and no row fails the test, and so does an import of an `ipu_*` package whose `:py_sources` are not in the test's data. Rows are per top-level package; "nothing imports X except Y" is expressed by listing X only in Y's row. Later issues add rows (E06-01, E08-03, E08-13) or delete the edges marked temporary (`ipu_emu` → `ipu_as`, planned for E03-18, went in E03-16 once the word codec removed its last use; `ipu_as` → `ipu_gen` in E08-14). E06-01 extended the schema: dotted subpackage keys (the longest key wins; `ipu_kernels.reference` may import only `ipu_isa`, stricter than "not `ipu_emu`" because the framework and the rest of `ipu_kernels` reach the emulator) and a `[deferred]` table of modules a key may import only inside a function (`torch` from `ipu_harness`). `ipu_harness` never imports `ipu_kernels`, not even inside a function (Q62); E06-09 and E06-16 load kernel-side modules with `importlib.import_module` on a name read from registry data, which is plugin loading, not an edge (the test sees only literal names). No issue adds a separate check. `//src/tools/ipu-isa:test_purity` stays as the run-time check that `ipu_isa` imports with only its own library on the path. | E03-02, E03-18, E06-01, E08-03, E08-13 |

## ISA and emulator

| Question | Default | Raised in |
|---|---|---|
| XMEM row count per format | The byte address space stays the same (512 MiB, allocated lazily). Addressable rows are that space divided by the row width. The hardware row limit is an open question in `requirements/open-questions.md`. | E03-13 |
| IMEM depth | Stays a constant in `ipu_isa`. Making it a run-time parameter is an open question. | E03-12 |
| What `HALT` does | Enters `HALTED` and reports kernel done. Fetching past the program end is fault F-2. | E03-20 |
| CR1 as an element scalar | CR0 and CR1 are hardware constants for 0 and 1. As an element scalar, CR1 reads as the encoding of 1.0 in the active format, so `MULT.VE … CR1` stays an identity multiply. As an LR or integer operand it is the integer 1. This is documented in the ISA reference. | E04-28 |
| Disabled faults | Only F-1 (the slot runs as `NOP`) and F-9 (the run continues) may be disabled. Disabling any other fault is a configuration error, until OQ-2 is answered. | E04-22 |
| Does a MULT product overflow set the accumulator overflow flag? | No, for now (the user's decision): a MULT (and an AAQ) float32 overflow keeps raising `OverflowError` from `store_acc`; only ACC and AGG stores record `ACC_OVERFLOW` (see "Arithmetic events"). Making it an event would move MULT's store to `store_acc_events`. | E04-23 |
| `pad_mode` that needs float lanes under an integer format | Kept as an `EmulatorError` (an open question, not a fault or a configuration error): see "Fault model". | E04-19 |
| R_CYCLIC alignment check | An LD.MULT.CYCLIC index off a slot boundary is F-4 in every format (`check_ld_mult_cyclic`). The wide-format byte-alignment `EmulatorError` is gone: byte offsets are always whole elements. | E04-19 |
| F-6 / F-7 | F-6 covers addresses beyond the XMEM address space. F-7 is never raised until tables exist. | E04-19 |
| Matmul benchmark kernel | `matmul_720x240_x128`, the largest standard case. Overridden for E04-02: it uses `matmul_384x192_x128`, because 720x240 takes about 22 s a run and `bench_emulator -- --quick` must finish in 30 s. E01-14's `kernel/*` keeps 720x240. | E04-02, E01-14 |
| Where the element codec lives | `ipu_isa.formats`, so the harness packs data without importing the emulator. | E04-13 |
| JSON schema validation | `jsonschema` as a test-only dependency. | E04-29 |
| Commit records and traces | Schemas `ipu_isa/schemas/commit_record.v1.json` and `trace.v1.json` (2020-12, `$id` ending in the semantic version; package data), read by `ipu_isa.trace_schema` (`load_schema`, `SCHEMA_VERSION`, and `isa_digest()`: SHA-256 of every instruction's slot, opcode, mnemonic, tag and operand types and widths, and every register; E03 had no digest). `ipu_emu.commit`: `CommitRecord` (+ `SlotOp`, `RegWrite`, `XmemWrite`, `FaultInfo`) with `to_json`/`from_json`, and `CommitCollector`, attached to a state through its cycle observers and the register and XMEM write observers; `ipu_emu.trace`: `trace_header`, `TraceWriter`, `read_trace` (JSON Lines). Choices: a scalar register write's `value` is a JSON number (the 32-bit rule), not the sketch's hex string; a write is the range a handler declared it may write, with its value at the end of the cycle (a whole-range export can report bytes left unchanged; the test checks every changed byte is covered and every value is the end state); `cycle` counts the trace's records; `break` means the word's BREAK fired and the word then retired; a word that ends in an emulator error, not a fault, leaves no record; a fault is recorded when it happens, through `IpuState.record_fault` (now the one place a fault is recorded, for the cycle's faults and F-9 alike) and `add_fault_observer`, with no writes (the schema says so: `outcome` fault requires `fault` and empty writes); the BREAK slot's op and verdict belong to the word at their PC only; ops of an EMULATOR slot, and writes to the wide-vector debug registers, carry `"tag": "emulator"`. `program_digest` is the SHA-256 of the encoded words (`word_bytes()` little-endian each), so any reader of the program can recompute it. The schemas stay 1.0.0 through review: none was published before. The BREAK slot's op is replaced at every evaluation, so a rerun at the same PC records it once; a word at a PC whose earlier run quit at its BREAK, when no BREAK issues before it begins (IMEM rewritten there without a BREAK, or a new program loaded with the collector attached), still lists that BREAK and is recorded as `break` (the collector has no run-start hook). A fault record lists no slots: nothing of a faulting word retires (E04-20), though observers saw its LR ops run before the check phase undid them. `RegFile.set_scalar` now tells the register observers (LR and CR writes were the one silent path). The schema-validity and state-difference tests run every timing probe in every mode it declares (together every slot, narrow and wide), not the whole suite. `EMULATOR_VERSION` mirrors `ipu-emu-py`'s pyproject version. | E04-29 |
| Fault model | `EmulatorFault(fault: FaultId, pc, detail)`; handlers raise it through `Ipu._fault` with the current PC (every slot but COND runs before the PC moves). `Cycle.step`/`retire`/`evaluate_break` record the halt through `IpuState.record_fault` (E04-29: the one place a fault is recorded, which tells the fault observers) and re-raise; an `XMemBoundsError` (new: `EmulatorError` and `ValueError`, raised by `XMem`'s own bounds check, a configuration error outside a cycle) becomes F-6 there. F-1 is checked once per cached schedule (`schedule_word`): an undefined opcode (negative codes too, which indexed from the end before), and every operand code that `ipu_isa.faults.reserved_operand_codes` reserves or that is past its operand type's width (`SlotPlan.operand_checks`; union columns are wider than some types, e.g. SET `src` in the 8-bit ADDBI column); the handler checks for `MultStageReg`, LD.MULT `dest` and INC.MODP2 `k` stayed as a second line until E04-20 deleted them (superseded: see "Precise faults"). `program_length` defaults to all of IMEM for a state whose IMEM is written directly; `load_program` sets it. Both run loops run while `halt is None`, so any PC past the program, IMEM included, is fetched and faults F-2. Deviation: `is_halted` is `halt is not None` *or* PC past IMEM, because the debugger's quit (`DebugSession.halt`, lane A's) still moves the PC there (`run_with_debug` stops on it after the callback); `_begin_run` clears `halt`, so a rerun after setting the PC works as before; a rerun that leaves the PC past IMEM (after a HALT) now faults F-2 there, where it returned 0 cycles. Fault priority within one word (IPU-FLT-8: e.g. a bad row checked before a bad cyclic index, F-3 before a handler's F-1) is E04-20's, with precision. Open questions kept as `EmulatorError`, not faults: `pad_mode` under integer lanes, QUANTIZE outside INT8 (OQ-20; the wide-mode R_CYCLIC alignment check is gone, see "R_CYCLIC alignment check"), and an ACC.STRIDE whose start plus element count overruns R_ACC (stage-accumulator 6.8 leaves it undefined; it was a `struct.error`). F-9 is E04-21's. | E04-19 |
| Cycle limit and run bookkeeping | `IpuState.cycle_limit` (`DEFAULT_CYCLE_LIMIT = 1_000_000` beside it in `ipu_state`; `emulator.DEFAULT_MAX_CYCLES` is the same constant, the one default of every runner and the apps' harness); 0 disables the check. The helper is `ipu_emu.run_clock.RunClock` (`begin_run(reset_stats=)`, `admit()`, `count_cycle()`, `end_run()`), not the spec's `run_control.RunControl`: that name is already the debugger's seam. `admit()` before each cycle faults F-9 at the PC of the word that would run, recording the halt, so `raise_on_fault=False` returns on it too; `end_run()` in a `finally` is the one place `total_cycles` is written (accumulated over earlier runs when `reset_stats=False`). A runner's `max_cycles` (default `None`: the state's own limit, which is programmable) is `state.cycle_limit` for that run only; `RunClock.end_run` restores the state's own. `reset_stats` is a flag argument beside `raise_on_fault`, as the spec's test asks (the code-conventions rule against flag arguments yields to it here). F-9 is recorded by `RunClock.admit` through `IpuState.record_fault`, as the cycle's faults are (E04-29). The lockstep test helpers (`emu_support.run_both`, `timing_probes`) keep their own loop guards; the apps' post-run `is_halted` checks no longer describe the limit. | E04-21 |
| Fault enable bits | `ipu_emu.fault_control.FaultControl` on `IpuState.faults`: `enable` (every `FaultId`, all set at construction; `reset()` sets them again and clears `sticky`) and `sticky`, which every fault sets whether it halts or not (`Cycle._halt_on`, `RunClock.admit`). Sticky flags are architectural state: a run does not clear them. F-1 disabled: `schedule_word` always builds a word whose slot holds an undefined opcode or a reserved operand code with that slot as its NOP and names it in `Schedule.reserved`; each cycle then faults or, with the bit clear, sets the flag and runs the NOP word, so a cached schedule never depends on the bit. F-9 disabled: `RunClock.admit` sets the flag and lets the run go on. F-2 to F-6: `set_enabled(..., False)` raises `ConfigurationError` (OQ-2 undecided), and `RunClock.begin_run` checks again first, so a direct `enable` write is refused before the run changes anything. F-7 and F-8 may be cleared (not modelled). E04-20's check phase does not exist yet, so the F-1 decision sits at the start of the cycle where E04-19 detects it. Step 4 (the reference API, E04-30, and the commit record, E04-29) lands with those issues. | E04-22 |
| Precise faults | Each instruction that can fault on register values has a pure predicate `check_<name>(ipu, **operands) -> (FaultId, detail) | None` beside its handler in `ipu_emu.slots` (LD.MULT, LD.MULT.CYCLIC, LD.MASK, ST.ACC, ST.AAQ: F-6 through `geometry.xmem_row_fault`; LD.MULT.CYCLIC F-4 first; ACC.RESHAPE F-5); `SlotPlan.check` binds it by name, and `Schedule.checks` lists a word's checked ops, so a word with none skips the phase. Deviation from the spec's scratch-copy design, same effect: the LR slot runs, then `Cycle._check` resolves each checked op's operands as its handler would (`Issuer.operands_of`: no counter, no observer) and evaluates the predicates; on a fault it restores the LR bank from the cycle's snapshot (the LRs are the only state written before that point: BREAK writes nothing, LR is the first slot after it, and no LR op bumps a statistic) and raises the lowest-numbered fault. F-1 (`Schedule.reserved`) and F-3 (`lr_conflict`) are decided before any slot runs and number below every predicate's fault. The handlers no longer raise faults: the F-4/F-5 raises and the unreachable F-1 ones (LD.MULT `dest`, INC.MODP2 `k`, which the fetch-time operand check catches) are gone, and `xmem_row_addr` raises a plain `EmulatorError` on a row no check phase saw (a direct handler call). Not precise, by design: `EmulatorError`s of the open questions and an `XMemBoundsError` from `XMem`'s own bounds check, which the row check makes unreachable for every load and store. Cost (bench_emulator --quick, cycles/s, two runs each): matmul_384x192_x128 8911 → 8493 (-4.7 %); fully_connected.int8 too noisy to separate (11.7k–16.4k either way). | E04-20 |
| Arithmetic events | The events are `ipu_isa.faults.ArithmeticEvent` (E03-15 declared them: `ACC_OVERFLOW`, `NAN_RESULT`, `QUANT_SATURATION`; the spec's `ACC_NAN` is `NAN_RESULT`). `IpuState.arith_flags` (a set, cleared only when the state is built or reset) and `record_arith(events)`, which tells `add_arith_observer`'s observers (the commit collector lists a word's events, sorted). `LaneCodec.store_acc_events(out, lanes)` stores the IEEE result and returns the events (overflow: a finite lane rounding to an infinity, or an integer lane outside int32, which wraps; NaN: a NaN lane); `acc_add`/`acc_sub` are the ACC/AGG sums before that store (an integer sum not yet wrapped, so the store sees it); `add`/`sub`, which wrap, now have no caller but their codec tests, which keep pinning them. The commit record schema's `arith_events` stay strings (narrowing them to an enum would be a major version, Q11); a test ties the names the emulator writes to `ArithmeticEvent`. Every ACC and AGG store goes through it, ACC.STRIDE and the AGG fold included. `store_acc` keeps its struct-compatible `OverflowError` for MULT (the spec's open question, for the user: MULT stores no event yet; an E7 product is at most 2^126, so only FP32 can overflow there) and AAQ (Q35, its overflow test unchanged). | E04-23 |
| Reference-model API | `ipu_emu.reference` (`__all__`: `API_VERSION = "1.0.0"`, `ReferenceModel`, `Status`, `RunState`, `RunResult`), a module, not a root export (E04-18 keeps the root curated); the emulator classes it uses are imported under `_` names. The contract is those names and the `ipu_emu.commit` records `step()` returns: the snapshot (`test_reference_api_contract.py`) pins signatures, dataclass field types, `RunState` values and every record field and `Outcome`, keyed by version, so a surface change fails until a new version's entry matches. `RunState` is `RUNNING`/`HALTED`/`FAULTED`; the model is `HALTED` after construction, `reset` and `load_program` (so the host may write), `RUNNING` once stepped, and after a HALT word `HALTED` with that word's PC (`HaltRecord.pc`), not the PC past it. Registers are `ipu_isa.registers.REGISTER_DEFINITIONS` names; `index` is the register within the bank (`lr`, `cr`: unsigned 32-bit int; the others: bytes of `size_bytes`); the emulator-only wide banks stay host-writable, since the wide formats' operands live there. Illegal host accesses (faults.md's AXI errors) raise `ConfigurationError`. Deviation from its glossary meaning (found before the first cycle): the host acts between cycles, never inside one, and a new error class would widen v1. `load_program` is a host write like the others: refused while running or faulted (IPU-FLT-7: after a fault only `reset` clears it), and it refuses a partial word, a negative or bool word, or one wider than the instruction word. `step()` runs `Cycle.step(honour_break=False)` inside a one-word `RunClock` with no limit (so its word counts toward `total_cycles`; F-9 is `run()`'s) and returns the word's record; a faulting step returns the fault record instead of raising, and `status` reads `FAULTED`. `run()` uses `RunClock` (E04-21) as the runners do, writes each record to `trace` as its word retires, and resets the statistics only on a run or step that starts a program. The model keeps no records: `CommitCollector.take()` (new) hands over the records made since the last take and keeps numbering; `reset` and `load_program` restart numbering at 0. A trace `run()` writes renumbers its records from 0 (the schema's `cycle`: records before this one in the trace; the schema bytes stay pinned). After a HALT word `step`/`run` raise `ConfigurationError` until `reset` or `load_program` (the spec names only the fault case). `reset(fmt)` keeps the spec's required `fmt` and the loaded program (hardware reset does not clear IMEM). The legacy `execute.py` wrappers are gone; The re-exports of `Ipu` and `BreakResult` from `execute.py` went in the final E04 review: callers import `Ipu` from `ipu_emu.ipu` and `CycleOutcome` from `ipu_emu.outcome`. Strict typing: strict mypy over all of `ipu_emu` reports 288 errors, so the module is its own private `py_library` (`reference_lib`, for mypy only) checked by `mypy_reference` with `ipu_emu_lib` as data; `mypy_test` (tools/typecheck.bzl) now takes `data`, merged into its own. The kernel test (`ipu-apps:test_reference_model_kernels`) runs identity, conv1x1 and softmax_columns_packed through the API and compares registers, XMEM and cycles with `run_until_complete`. | E04-30 |

| Reference-model API 1.3.0: the debug escape hatch and alias profiles | Lane B's E06-12 (the runner owns debug and profile) needs them through the stable API. `ReferenceModel.debug_run(callback, break_on_entry=False, *, max_cycles=None, control=None) -> RunResult` runs `ipu_emu.emulator.run_with_debug` on the model's state: the callback gets the internal `IpuState` and the cycle count and returns a `DebugAction`, and `control` is a `RunControl`; those two types are documented as outside the contract (the one escape hatch), while the method and its `RunResult` follow the version. It writes no trace and forgets a BREAK stop it quit at (`CommitCollector.drop_stop`), so the next word is recorded as a plain step. A bare `QUIT` leaves the model `RUNNING` at that PC, so a later step or run carries on; `ipu_debug`'s quit also moves the PC past IMEM, and `status` reads `HALTED` there (the host may write; stepping needs `reset` or `load_program`). `attach_alias_profile(profile)` (only while halted; a non-profile, or one already recording a live model, is refused; attaching another profile detaches the one before) sets the state's profile and rebuilds the engine, which binds the profile's observer when built; `alias_profile()` returns it. `AliasProfile` is not added to `__all__`: it is the emulator's class, named only in the signature. `API_VERSION = "1.3.0"`; the snapshot gains a 1.3.0 entry. | E04-30 (follow-up) |

| Conformance suite | Where the data lives (the spec's open question): `src/tools/ipu-isa/conformance/`, beside the ISA it pins, not inside the package. 176 cases there (784 KB of files, about 145 KB compressed; filling every register made 1.9 MB), each `program.asm`, `program.bin`, `setup.json` (schema `setup.schema.json` beside the cases: format, `emulator_only`, `max_cycles`, `fault_enables`, every register to write, as `value` for `lr`/`cr` and `hex` otherwise, and the non-zero XMEM regions: every register and byte not listed starts at zero, but the constants CR0 and CR1, so a register whose reset value is not zero, such as CR15 or `r_mask`, is always listed and a consumer needs no emulator reset values; `format` and register `name` are enums the test ties to `ipu_isa`, and the README's bank table likewise) and `expected.trace.jsonl`; a `README.md` is the RTL testbench's usage note.
