# docs: a Kernels section covering the family, its coverage, and how to add more

### Description

The site has no home for applications. `building-applications.md` explains the
*mechanics* of writing one — file layout, Bazel targets, harness structure —
but nothing says **which kernels exist**, what each handles, or how the emulator
knows. Softmax in particular is undocumented outside its own docstrings.

This adds a **Kernels** tab with four pages.

**`kernels/index.md`** — the section overview: what a kernel is, how to ask the
registry for one, and what is currently registered. Notes that the convolution
and fully-connected families exist but are not yet registered, so nobody
concludes from a short table that they are missing.

**`kernels/softmax.md`** — the softmax family in particular, and the page that
did not exist before:

- how to pick a kernel, with the routing tables generated by probing the
  registry;
- the shared base-2 formulation (`c = log2(e)`, so the native `exp2` applies
  directly) and the four-pass structure all five share;
- each kernel's specialisation — partition packing below 128, cross-chunk
  running reduction above it, and why the column kernels need no `AGG` at all
  (every lane is an independent column, so the reduction stays in-lane);
- the group loop, framed as the correctness requirement it is rather than loop
  bookkeeping;
- the data-layout contract: output file layout equals input file layout;
- measured cost, taken from the committed benchmarks.

**`app-coverage.md`** — how the emulator knows which kernel implements a
computation: declaration, discovery at any nesting depth, cost-based resolution,
role-keyed shape bundles, and what keeps it honest. States the failure it exists
to prevent, with the concrete instance from this codebase: a rule written twice
drifts, and the second copy is the one that rots.

**`adding-applications.md`** — the contributor guide: what you deliver, how to
write a `KernelSpec`, and the two rules that are easy to get wrong —

- `supports` states a kernel's TRUE domain, not the range where you would prefer
  it chosen; `cost` decides the winner;
- constructor guards delegate to `SPEC.guard()` rather than restating bounds.

Plus layer-adapter obligations (refuse config you do not model; refuse
look-alike layers), what the generic conformance suites check for you, and a
checklist ending in `bazel test //src/tools/ipu-apps:all`.

### Why a new tab rather than filing them under existing ones

Coverage and contribution are two halves of one subject, and splitting them
across "Programming the IPU" and "Contributing" means a reader looking for
"what can this machine compute?" has to know to look in two places. Grouping
them puts the question and the answer next to each other, and gives the
per-family pages somewhere to live as more families are registered.

`building-applications.md` stays where it is: it is about the mechanics of
writing an application, which is a different question.
