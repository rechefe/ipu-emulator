Where a row's format lives

An XMEM row written by AaQ is 128 bytes of elements plus a 16-bit metadata word. To turn those bytes back into numbers, a reader needs a third thing that is in neither: the format, which says how each byte splits into exponent and mantissa bits.

Spec update (master 0511213)
  • The architecture specs name the format in a quantizion_format CR operand of ACTIVATE.QUANTIZE and of every MULT instruction. The microarchitecture spec and the cache-unit spec still make it a table property. The course follows the architecture specs (spec audit #3, #19).
  • In the architecture spec ACTIVATE.QUANTIZE also stores the row; the microarchitecture spec keeps a separate ST.AAQ (audit #1).
  • The MULT architecture spec now specifies the decode used below.

The job of the scale

AaQ takes 128 FP32 values from R_ACC and writes 128 bytes. One byte cannot cover FP32's range, so the 128 elements share one exponent, the row's scale s. Each element then stores only how far it sits below that scale, plus a few mantissa bits.[AaQ §5.1]

AaQ computes s as the largest raw FP32 exponent in the row and stores it as e8m0: an 8-bit exponent, a power of two with no mantissa.[AaQ §5.1]

The industry calls this block scaling. The OCP Microscaling (MX) standard shares one E8M0 scale across 32 elements;[CUTLASS] [AWS Neuron] AaQ shares one across a whole 128-element row.

Why the metadata alone is not enough

Take a row whose largest value is 3.2. In FP32, 3.2 = 1.6 × 21, a biased exponent of 128, so s = 128. One element is 0.4 = 1.6 × 2−2, biased exponent 125, which sits E = 128 − 125 = 3 binades below the scale.

With format e4 (fe = 4), AaQ stores exponent field 3 and rounds 0.6 to 3 mantissa bits (5/8). The byte is 0 0011 101 = 0x1D, which decodes to 1.625 × 2128−127−3 = 0.40625.

Now read the same byte with the same scale but fe = 2. The bits split differently and give 3.8125. Change fe below and watch the violet field move.

Decode a byte

The scale says where the row's values are. The format's fe says how to split each byte. A reader needs both, and they come from different places.

Exception, dynamic format. When the format is dynamic (dynamic_static = 1), it fixes only "signed, 8 bits". AaQ picks E1M6 or E2M5 for each row and records the choice in that row's dynamic_exponent bit. So for dynamic data, fe comes from the metadata word instead.[AaQ §5.1.1]

Explain it back

In two sentences, tell an RTL engineer why a row's metadata word alone cannot decode the row. Type it, then compare.

The metadata gives the row's scale, which says where its values sit, but not how each byte splits into exponent and mantissa bits. That split, fe, belongs to the format: a quantizion_format CR in the architecture specs, a table property in the microarchitecture spec. Only dynamic quantization moves it into the row, through dynamic_exponent.

What this means for the emulator

Today the emulator's XMEM is a flat byte array, and one element format applies to the whole run (ADR 0003). Matching the specs needs at least these pieces:

  • XMEM: a 16-bit metadata word beside every 128-byte row.
  • Format operand: ACTIVATE.QUANTIZE and every MULT instruction read a quantizion_format CR, as the architecture specs define.
  • AaQ: the spec's ACTIVATE.QUANTIZE (scale, encoding, dynamic choice) and the LUT load. Today's version moves to an emulator-only slot so old kernels keep working.
  • Store: ACTIVATE.QUANTIZE writes 128 bytes plus the metadata word to table_id, table_offset itself. The microarchitecture spec keeps a separate ST.AAQ (audit #1).
  • LD and MULT: carry each row's metadata into the registers and expand the elements to FP32 before multiplying.
Where the spec stops
  • Where the format comes from differs between the architecture and microarchitecture specs, and the AaQ and MULT architecture specs lay out the quantizion_format CR differently (audit #3, #17).
  • The MULT architecture spec lists a third metadata item, dynamic_static, that nothing writes (audit #18).

Settled since the first version of this lesson: the decode is specified (ARCH MULT §3.2.1), and fe = 0 is invalid.
