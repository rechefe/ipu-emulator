Quantizing a row, step by step

AaQ turns 128 FP32 values into 128 bytes and one scale in five steps: pick the scale, measure each element's distance from it, choose a branch, round, and pack. Two rounding edge cases decide what happens when a mantissa rounds up and carries.

The five steps

All steps work on the FP32 bits of each activated element: sign S, raw (biased) exponent e, and the 23-bit mantissa with its implicit leading 1.[AaQ §5.1]

  1. Pick the scale. s = max(e) over the row's elements. The scale is the raw exponent of the largest element, stored as e8m0.
  2. Measure the distance. E = s − e for each element. E ≥ 0 always; E = 0 for the element(s) that set the scale.
  3. Choose the branch. If E < 2fe − 1, the direct branch stores Exp = E. Otherwise the clamp branch stores Exp = 2fe − 1, the all-ones field.
  4. Round the mantissa to fm bits, round to nearest. The clamp branch first shifts 1.M right by E − (2fe − 1) + 1, so small elements keep their magnitude instead of flushing to zero.
  5. Pack {S, Exp, M} at the top of the byte, with zeros below when W < 8.

The two edge cases

Both happen when rounding carries out of the fm mantissa bits, as when 1.11…1 rounds up to 10.00…0.

CaseWhenResultExample (s = 128)
Edge 1, E > 0Direct branch carriesOne binade up: Exp = E − 1, M = 01.99 → 0x00 = 2
Edge 1, E = 0The top binade carriesNo binade above the scale: saturate, M = 2fm − 13.99 alone → 0x07 = 3.75
Edge 2Clamp branch carries to 1.0Smallest direct exponent: Exp = 2fe − 2, M = 0fe = 2: 0.4975 → 0x40 = 0.5

Edge 1 at E = 0 costs the most. A row whose largest value is 3.99 stores it as 3.75, an error of 0.24, because the scale comes from the raw exponent before rounding. A scale one higher would store 4.0 exactly; the spec does not choose that.

Explain it back

In three sentences, explain to an RTL engineer what edge 1 and edge 2 are and why they resolve differently.

Both are the same event: rounding carries out of the fm mantissa bits. In the direct branch the value moved up one binade, so Exp drops by one and M clears, except at E = 0, where no binade sits above the scale and the element saturates at the largest code. In the clamp branch the shifted fraction rounded up to 1.0, which is exactly the smallest direct value, so it is re-encoded as Exp = 2^fe − 2, M = 0.

What this means for the emulator

  • Bit-exact integer arithmetic. The quantizer works on the FP32 bit fields (struct packing in Python), not on doubles. The emulator's AaQ path today uses Python round() on doubles (src/ipu-emu/src/ipu_emu/slots/aaq.py), which rounds ties to even.
  • One unit test per rule. Each branch, both edges, zero, and the worked example above become tests with exact expected bytes.
  • Decisions before conformance. The tie rule, ±inf and NaN (OQ-22), and FP32 subnormals must match the RTL; agree them with the AaQ spec owner first.
Where the spec stops
  • §5.1 writes s = max(e[i] for i in 0..254) for a 128-element row; read it as the 128 elements (OQ-25 notes it).
  • The spec does not say whether elements beyond valid_elements, or masked by partition_mask, count toward s. §3.1 says masked elements "do not participate".
  • "Round to nearest" has no tie rule.
  • FP32 subnormals are "always treated as normalized": a subnormal input gets an implicit 1 it does not have.
  • Edge 1 at E = 0 saturates rather than raising the scale; worth confirming this is intended.
