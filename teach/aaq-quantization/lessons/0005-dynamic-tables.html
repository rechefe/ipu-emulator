Dynamic quantization: E1M6 or E2M5 per row

In dynamic mode, AaQ chooses one of two splits for each row: E1M6, finer near the row's scale, or E2M5, finer below it. It writes the choice to the row's dynamic_exponent bit, and a reader takes fe from there.

Spec update (master 0511213)

The architecture spec (ARCH-stage-aaq-str.md §4.3.2.3) keeps the dynamic rule, its step table and its worked example unchanged. What moved is where "dynamic" is set: in the quantizion_format CR that ACTIVATE.QUANTIZE names, not in a table property. The MULT spec marks a dynamic input with nx_format = 0 in its own format CR, which has a different layout (audit #17).

What dynamic mode fixes

dynamic_static = 1 (bits [31:24] of the AaQ format CR) fixes only "signed, 8 bits wide": sign = 1, num_bits = 8. The CR's exponent_format field is ignored. The two legal splits are E1M6 (fe = 1) and E2M5 (fe = 2).[ARCH AaQ §3.1] [§4.3.2.3] The microarchitecture and cache-unit specs hold the same flag as format[8] of the destination table (audit #3, #19).

AaQ computes the scale s exactly as in static mode: the largest raw exponent among the active elements.[§4.3.2.1] Only the split changes. The metadata word records it: dynamic_exponent = 0 for E1M6, 1 for E2M5.[§4.3.3]

The trade

With S = s − 127, the decode from lesson 1 gives each split's step, the distance between neighbouring values, at each distance E below the scale:

E1M6 has one step everywhere: under the quantizer (ARCH §4.3.2.2) it is a sign plus a 7-bit magnitude times 2S−6, block-scaled fixed point. E2M5 gives up one bit in the top binade to gain one bit in every binade from E = 2 down. A row whose values crowd near its maximum prefers E1M6; a row with many small values prefers E2M5.

The rule

AaQ scores the row with two integer sums.[ARCH AaQ §4.3.2.3] [MAS §5.1.1] fm1 = W − 2 is E1M6's mantissa width (6 for W = 8); err1 and err2 are an element's truncation errors under each split.

ElementAdds toTerm
E = 0A, the cost of choosing E2M5RTN(|err2² − err1²| · 22·fm1)
E = 1nothingdon't care
1 < E ≤ fm1 + 2B, the cost of choosing E1M6RTN(|err2² − err1²| · 22·(fm1+1))
E > fm1 + 2nothingtoo small for both

sum(B) − 4 · sum(A) < 0 → E1M6, dynamic_exponent = 0; otherwise E2M5, dynamic_exponent = 1

RTN rounds half up. The factor 4 converts units: B's multiplier is exactly four times A's, so 4 · sum(A) and sum(B) measure the same squared error.

The spec's worked example

Ten values, s unbiased 0, signed W = 6 (fm1 = 4). The spec gets sum(A) = 5, sum(B) = 2, so 2 − 20 = −18 and E1M6. The widget reproduces every term. The last two columns quantize each value with the quantizer under each split.

Does the rule pick the better split?

The rule estimates which split loses less precision; it does not quantize the row twice. On the worked example both agree: E1M6 has the lower quantized squared error. The row below, at W = 8, scores −7 and picks E1M6, but E2M5 quantizes it with less than half the squared error (6.4e-5 against 1.4e-4).

Try your own row (W = 8)

Add small values and watch sum(B) grow; add values near the maximum and watch sum(A) grow.

In a quick test, 2000 random 16-element rows with magnitudes spread over 8 binades, the rule disagreed with the split of lower quantized squared error on 1058 rows. It disagreed with its own unrounded terms on 238. The numbers depend on the data; they show the rule is an estimate built on its own error model, described under "Where the spec stops".

Practice

Explain it back

In three sentences, explain to an RTL engineer what AaQ decides for a row in dynamic mode, from which elements, and where the answer goes.

For each row quantized in dynamic mode, AaQ picks E1M6 or E2M5 with the same scale it would use in static mode. Elements at the scale (E = 0) add to A, the precision E2M5 would lose; elements from E = 2 to fm1 + 2 add to B, the precision E1M6 would lose; E1M6 wins when sum(B) − 4 · sum(A) is negative. The choice goes to bit 8 of the row's metadata word, where every reader takes fe from (MULT does so when its format CR says nx_format = 0).

What this means for the emulator

  • The selection runs per row, inside the hardware ACTIVATE.QUANTIZE, before the elements are encoded with the chosen fe.
  • Bit-exact integer arithmetic. The terms are integers after RTN, so the emulator can match RTL exactly, once the error model below is settled.
  • The metadata word carries the choice. ACTIVATE.QUANTIZE writes dynamic_exponent to bit 8 when it stores the row; static mode writes 0. A MULT instruction whose format CR has nx_format = 0 takes fe from that bit, kept with each register's metadata.
  • One flag, two CR layouts. AaQ reads dynamic_static from bits [31:24] of its format CR, MULT reads nx_format = 0 from bits [15:8] of its own. MULT's metadata list also names a dynamic_static bit that nobody writes (audit #17, #18).
  • A first test exists. The spec's worked example (sum(A) = 5, sum(B) = 2, E1M6) is a ready-made unit test.
Where the spec stops

ARCH §4.3.2.3 repeats MAS §5.1.1 word for word on these points, so each holds for both specs.

  • Two step models. The dynamic-selection step table and its worked example use E1M6 step 2S−min(E,1)−fm1 and E2M5 step 2S−min(E,3)−fm1+1. The quantizer's clamp branch (ARCH §4.3.2.2) is one bit coarser: 2S−fm1 and 2S−fm1−1. Under the table's model E = 1 is not a tie: the example's 0.67 has err1 = 0.01375 and err2 = 0.045.
  • Truncation against rounding. The rule scores truncation errors; the quantizer it chooses for rounds to nearest.
  • Absolute value. |err2² − err1²| drops the sign, so an element where the "worse" split happens to be closer still adds cost.
  • W in the example. The example uses W = 6; dynamic mode allows only signed W = 8 (ARCH §4.3.2.3, MAS §5.1 note).
  • Inputs. The spec does not say whether errors come from the FP32 value or its magnitude for negative elements. The widget uses the FP32 magnitude.
  • Where the flag lives. A CR field in ARCH, a table property in MAS and the cache unit; and the AaQ and MULT format CRs disagree on layout (audit #3, #17, #19).
