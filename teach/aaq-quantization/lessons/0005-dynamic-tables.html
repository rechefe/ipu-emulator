Dynamic tables: E1M6 or E2M5 per row

In a dynamic table, AaQ chooses one of two splits for each row: E1M6, finer near the row's scale, or E2M5, finer below it. It writes the choice to the row's dynamic_exponent bit, and a reader takes fe from there.

What a dynamic table fixes

A table format with format[8] = 1 fixes only "signed, 8 bits wide". Its fe field is ignored. The two legal splits are E1M6 (fe = 1) and E2M5 (fe = 2).[AaQ §3.3] [§5.1 note]

AaQ computes the scale s exactly as for a static table: the largest raw exponent in the row. Only the split changes. The metadata word records it: dynamic_exponent = 0 for E1M6, 1 for E2M5.[AaQ §3.2]

The trade

With S = s − 127, the decode from lesson 1 gives each split's step, the distance between neighbouring values, at each distance E below the scale:

E1M6 has one step everywhere: under §5.1 it is a sign plus a 7-bit magnitude times 2S−6, block-scaled fixed point. E2M5 gives up one bit in the top binade to gain one bit in every binade from E = 2 down. A row whose values crowd near its maximum prefers E1M6; a row with many small values prefers E2M5.

The rule

AaQ scores the row with two integer sums.[AaQ §5.1.1] fm1 = W − 2 is E1M6's mantissa width (6 for W = 8); err1 and err2 are an element's truncation errors under each split.

ElementAdds toTerm
E = 0A, the cost of choosing E2M5RTN(|err2² − err1²| · 22·fm1)
E = 1nothingdon't care
1 < E ≤ fm1 + 2B, the cost of choosing E1M6RTN(|err2² − err1²| · 22·(fm1+1))
E > fm1 + 2nothingtoo small for both

sum(B) − 4 · sum(A) < 0 → E1M6, dynamic_exponent = 0; otherwise E2M5, dynamic_exponent = 1

RTN rounds half up. The factor 4 converts units: B's multiplier is exactly four times A's, so 4 · sum(A) and sum(B) measure the same squared error.

The spec's worked example

Ten values, s unbiased 0, signed W = 6 (fm1 = 4). The spec gets sum(A) = 5, sum(B) = 2, so 2 − 20 = −18 and E1M6. The widget reproduces every term. The last two columns quantize each value with §5.1 under each split.

Does the rule pick the better split?

The rule estimates which split loses less precision; it does not quantize the row twice. On the worked example both agree: E1M6 has the lower §5.1 squared error. The row below, at W = 8, scores −7 and picks E1M6, but E2M5 quantizes it with less than half the squared error (6.4e-5 against 1.4e-4).

Try your own row (W = 8)

Add small values and watch sum(B) grow; add values near the maximum and watch sum(A) grow.

In a quick test, 2000 random 16-element rows with magnitudes spread over 8 binades, the rule disagreed with the split of lower §5.1 squared error on 1058 rows. It disagreed with its own unrounded terms on 238. The numbers depend on the data; they show the rule is an estimate built on its own error model, described under "Where the spec stops".

Explain it back

In three sentences, explain to an RTL engineer what AaQ decides for a dynamic row, from which elements, and where the answer goes.

For each row of a dynamic table, AaQ picks E1M6 or E2M5 with the same scale it would use for a static table. Elements at the scale (E = 0) add to A, the precision E2M5 would lose; elements from E = 2 to fm1 + 2 add to B, the precision E1M6 would lose; E1M6 wins when sum(B) − 4 · sum(A) is negative. The choice goes to bit 8 of the row's metadata word, where every reader takes fe from.

What this means for the emulator

  • The selection runs per row, inside the hardware ACTIVATE.QUANTIZE, before the elements are encoded with the chosen fe.
  • Bit-exact integer arithmetic. The terms are integers after RTN, so the emulator can match RTL exactly, once the error model below is settled.
  • The metadata word carries the choice. ST.AAQ writes dynamic_exponent to bit 8; static tables write 0. A reader of a dynamic table takes fe from bit 8 instead of the table format.
  • A first test exists. The spec's worked example (sum(A) = 5, sum(B) = 2, E1M6) is a ready-made unit test.
Where the spec stops
  • Two step models. The §5.1.1 table and its worked example use E1M6 step 2S−min(E,1)−fm1 and E2M5 step 2S−min(E,3)−fm1+1. §5.1's clamp branch is one bit coarser: 2S−fm1 and 2S−fm1−1. Under the table's model E = 1 is not a tie: the example's 0.67 has err1 = 0.01375 and err2 = 0.045.
  • Truncation against rounding. The rule scores truncation errors; the quantizer it chooses for rounds to nearest.
  • Absolute value. |err2² − err1²| drops the sign, so an element where the "worse" split happens to be closer still adds cost.
  • W in the example. The example uses W = 6; the §5.1 note allows dynamic tables only at signed W = 8.
  • Inputs. The spec does not say whether errors come from the FP32 value or its magnitude for negative elements. The widget uses the FP32 magnitude.
