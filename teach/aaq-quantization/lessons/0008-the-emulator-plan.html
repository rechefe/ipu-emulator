Lesson 8 · about 15 minutes

The emulator plan: old and new AaQ side by side

The emulator keeps today's ACTIVATE.QUANTIZE for the existing kernels and adds the hardware AaQ beside it. Eight reviewable PRs get there. Six design questions are still open; this lesson ends with a board where you answer them.

Settled so far

QuestionDecision
Q1 Backward compatibilityKernel goldens never change. Kernel sources may change mechanically, for example a rename. Old binaries are not supported.
Q2 CoexistenceThe old instruction moves to a new EMULATOR-tagged slot. The hardware AAQ slot holds NOP, the spec's ACTIVATE.QUANTIZE and the LUT load.
Q3 XMEM metadataA side store in XMem: one 16-bit metadata word per 128-byte row.
Q4 LUTLUT-load bits stored exactly; exact-math evaluation until the spec defines LUT indexing. Exact match is the goal.
Q5 Format sourceA table format per input and output array, declared in kernel.toml.
Q6 ReadersMULT reads each row's metadata and expands the elements to FP32. This needs a proposed MULT spec first.

The tag belongs to the whole slot: an instruction's tag is its slot's, and the schema rejects a mismatch (instruction_spec.py, _instruction_tag). EMULATOR slots come after every HARDWARE slot in LAYOUT_ORDER, so the hardware word is the top of the emulator word (slots.py). The assembler refuses an EMULATOR instruction for --target hardware (encode.py). ST.ACC in the acc_store slot already works this way.

What "goldens never change" costs

  • Kernel sources. 64 of the 67 kernels call ACTIVATE.QUANTIZE, and the same 64 call ST.AAQ. A rename (Q7) edits all 64 .asm files by find-and-replace.
  • Baselines move, with reasons. Assembled-program digests, field-name snapshots, disassembly text, the ISA snapshot and the SV package golden all change when the AAQ slot changes. tools/update_baselines.sh regenerates them; the PR names why each one moved (code conventions, Baselines).
  • The wire format changes. The AAQ opcode grows from 1 bit (NOP, ACTIVATE_QUANTIZE) to 2 bits. Today AAQ_SLOT_T_WIDTH = 9 and IPU_COMPOUND_INST_WIDTH = 155. A 3-bit function_type instead of today's 4-bit keyword may keep the slot at 9 bits, but the opcode enum still changes for the downstream RTL repo. Call it out in the PR as breaking; tools/sv_localparam_diff.sh shows the exact width changes.
  • The "one edit" test stays honest. KNOWN_MANUAL_EDITS in test_one_edit_end_to_end.py is empty. A new slot must not add a manual edit outside the spec and the handler.
A fact that changes Q8

In INT8, ST.AAQ writes all 512 bytes of POST_AAQ_REG at a 128-byte row, so it also writes the next three rows (store.py). Some goldens depend on this:

  • kernels/conformance/vector_tour declares its relu output as 4 × 128 bytes: "128 results, then 384 zeros".
  • kernels/projections/proj_p4 (INT8 case) advances one row per store; each store's spill is overwritten by the next, and the last spills three rows past the output.
  • The unit test test_str_post_aaq_reg_writes_post_aaq_reg_512_to_xmem pins the 512-byte write in the default INT8 state.

So a 128-byte ST.AAQ in INT8 for legacy data can change a golden. The safe reading of Q8: ST.AAQ stores 128 bytes plus metadata only for data written by the hardware instruction, and keeps the 512-byte store for legacy data.

Practice

Questions 5 to 9 come from lessons 1 to 7.

Explain it back

In three sentences, tell a reviewer how PR 4 proves it kept backward compatibility.

PR 4 moves the legacy instruction to a new EMULATOR slot and renames it in 64 kernels by find-and-replace, and every kernel golden still passes unchanged. The baselines that move (digests, field names, disassembly, ISA snapshot, SV package slot list) are regenerated with tools/update_baselines.sh, and the PR says why each moved. --target hardware now rejects the legacy instruction, which shows the hardware word no longer contains it.

Where the spec stops
  • No MULT spec: PR 1 writes the expansion rule as a proposal.
  • LUT indexing and the asymetric and range_mode encodings are TBD (OQ-25), so PR 6 cannot be bit-exact yet.
  • Where AaQ's format input comes from is not specified (Q9).
  • The tie rule, ±inf and NaN inputs, and fe = 0 (lessons 3 and 4) need answers before PR 5 can match RTL bit for bit.
