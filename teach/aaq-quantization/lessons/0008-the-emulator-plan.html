The emulator plan: old and new AaQ side by side

The emulator keeps today's AaQ for the existing kernels, adds the hardware AaQ of the architecture spec beside it, and replaces its own E1–E7 with the hardware's NX8. Ten reviewable PRs get there. Nine questions are still open; this lesson ends with a board where you answer them.

Settled

An instruction's tag is its slot's; the schema rejects a mismatch (instruction_spec.py). EMULATOR slots come after every HARDWARE slot in LAYOUT_ORDER, so the hardware word is the top of the emulator word (slots.py). ST.ACC in the acc_store slot already works this way.

What the change costs

  • Kernel sources. 64 of the 67 kernels call ACTIVATE.QUANTIZE and ST.AAQ; they get a mechanical rename to the legacy names. Every MULT instruction gains a quantizion_format operand, so every kernel that multiplies changes mechanically too (R6).
  • Baselines move, with reasons. Assembled-program digests, field-name snapshots, disassembly text, the ISA snapshot and the SV package golden change with the slots. tools/update_baselines.sh regenerates them; the PR says why each moved (code conventions, Baselines).
  • The wire format breaks. Today AAQ_SLOT_T_WIDTH = 9, MULT_SLOT_T_WIDTH = 23 and IPU_COMPOUND_INST_WIDTH = 155. The hardware AAQ slot grows to about 21 bits (2-bit opcode, 3-bit activation, three 4-bit CRs, one 4-bit LR), and each MULT instruction gains 4 bits. Call it out as breaking; tools/sv_localparam_diff.sh shows the exact widths.
  • The "one edit" test stays honest. KNOWN_MANUAL_EDITS in test_one_edit_end_to_end.py is empty. New slots and operands must not add a manual edit outside the spec and the handler.
Why legacy ST.AAQ must stay

ARCH has no ST.AAQ. In INT8, today's ST.AAQ writes all 512 bytes of POST_AAQ_REG at a 128-byte row, so it also writes the next three rows (store.py). kernels/conformance/vector_tour and kernels/projections/proj_p4 depend on that, and test_str_post_aaq_reg_writes_post_aaq_reg_512_to_xmem pins it. Legacy kernels keep their goldens only if the 512-byte store survives (R2).

Practice

Questions 6 to 9 come from lessons 1, 4, 5 and 7.

Explain it back

In three sentences, tell the spec owner why the emulator follows the architecture spec where it disagrees with the microarchitecture spec, and what you need from them.

The architecture spec defines what a program can observe, and the emulator is the reference for programs, so it implements ARCH. Where MAS describes different visible behaviour (the separate ST.AAQ, the activation encodings, NaN for inactive elements, special values, the LUT metadata), one of the two is wrong, and both are meant to hold. We need MAS corrected to ARCH, one quantizion_format layout shared by AaQ and MULT, and definitions for NX8 NaN and inf and for the LUT entry format.

Where the spec stops
  • AaQ and MULT disagree on the quantizion_format layout, and MULT expects a dynamic_static metadata bit nobody writes (audit #17, #18).
  • NX8 has no defined NaN or inf, yet ARCH AaQ writes NaN for inactive elements (#13, #22).
  • The LUT's 17-bit entry format and interpolation are undefined, so PR 8 cannot be bit-exact yet (#23).
  • LOAD_LUT's table_id and table_offset operands are unused by its operation (#11).
  • MAS still describes a separate ST.AAQ, other activation encodings, other special values and a 75-bit LUT metadata block (#1–#12).
