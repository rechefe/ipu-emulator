Row anatomy

What an AaQ-written XMEM row holds, where its format comes from, and how to decode one NX8 element.

Spec update (master 0511213)

The architecture specs take the format from a quantizion_format CR and let ACTIVATE.QUANTIZE store the row; the microarchitecture and cache-unit specs use a table format and ST.AAQ. See the spec audit.

Source: cache unit §4, §6. The AaQ payload (AaQ §3.2) is 1024 + 8 + 1 = 1033 bits.

Microarchitecture and cache unit: a 9-bit table property.

BitsFieldMeaning
[8]dynamic0 = static, 1 = dynamic (signed, W = 8, E1M6 or E2M5 per row).
[7]sign0 = unsigned, 1 = signed.
[6:4]feExponent bits, 1–7 (0 invalid). Ignored when dynamic.
[3:0]WElement width, 1–8. Mantissa fm = W − fe − sign; low bits zero-padded when W < 8.

Source: AaQ §3.3, cache unit §5.

Decode one element (signed, W = 8)

Exponent fieldValue
Exp < 2fe − 1±(1 + M/2fm) · 2s − 127 − Exp
Exp = 2fe − 1 (clamp)±(M/2fm) · 2s − 127 − 2fe + 2

A larger exponent field means a smaller value: Exp counts binades below the scale. NX8 is the hardware's only 8-bit float family; "E4" means NX8 e4. The emulator's old E1–E7 (biased, no scale) are being retired.

Specified in ARCH MULT §3.2.1; it inverts the quantizer of ARCH AaQ §4.3.2.

Worked example: s = 128, fe = 4, byte 0x1D = 0 0011 101 → (1 + 5/8) · 2−2 = 0.40625. The same byte with fe = 2 → 3.8125.

Open gaps

  • NX8 NaN and inf: undefined (audit #13, #22).
  • LUT entry format and interpolation: undefined (audit #23).
