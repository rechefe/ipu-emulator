Architecture against microarchitecture

Where ARCH-stage-aaq-str.md, MAS-stage-aaq-str.md, ARCH-stage-mult.md and cache-unit.md agree, and where both cannot hold.

The test

The architecture spec defines what a program can observe: instructions, operands, encodings and results. The microarchitecture spec defines how the stage produces them: signals, widths and internal registers. A difference is layering when the microarchitecture can implement the architecture as written. It is a contradiction when a program could tell which spec the hardware follows. A gap is something neither spec defines.

Proposed rule for the emulator: the emulator implements the architecture. Each contradiction goes to the spec owner, who corrects the microarchitecture spec.

What to ask the spec owners

  1. Update MAS to the ARCH ISA: merged store, five operands, CR format, 0–6 activation encodings, NaN for inactive elements, ARCH special values, 46-bit LUT metadata, LOAD_LUT.
  2. Pick one quantizion_format layout for AaQ and MULT (#17).
  3. Decide whether row metadata carries dynamic_static (#18).
  4. Drop or redefine the cache unit's table format (#19).
  5. Define NX8 NaN and inf, or remove them (#13, #22).
  6. Define the LUT entry format and interpolation (#23).
  7. Say what LOAD_LUT's table_id and table_offset do (#11).
  8. Rename the ARCH mnemonics to the repo standard, or change the standard (#20).
