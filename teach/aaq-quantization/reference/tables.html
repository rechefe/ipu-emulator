Kernel life cycle

  1. Host writes IMEM bank k, CR bank k and table set k, then commits: tables_valid[k] = 1.
  2. Host sends ARM. Context k locks.
  3. DMA may fill banks for table set k before the context is active (CU-16).
  4. Kernel runs. The cache agent stalls on each miss until the bank is published.
  5. On kernel_done, the cache unit drains written banks and frees the rest (CU-17), then accepts writes to table set k again.
